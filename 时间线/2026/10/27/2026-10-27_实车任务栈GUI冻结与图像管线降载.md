# 实车 mission_controller GUI 冻结与图像管线降载

> 整理日期：2026年10月27日 21:48
> 项目：ROS仿真车 ｜ 状态：已解决 ｜ 标签：`报错排查` `ros` `真车` `perception` `python环境`

## 背景 / 目标

实车执行 `roslaunch aic26_bringup bringup.launch mode:=mission backend:=real use_rviz:=false`
后，所有节点都起来了，但**车一条目标都没收到**。表面线索是 `camera_view` 报
`cannot open display` 退出；实际根因是 `mission_controller` 的 tkinter 结果窗口把整个进程
冻结在 X 连接的 C 调用里。修好之后又顺手把实车图像链路在空闲时浪费的 CPU 降下来，
避免 10 Hz 控制环掉频。

## 环境信息

- 车端：Ubuntu 20.04 + ROS Noetic，Intel N100（4 核 4 线程）
- 工作区：`/home/mowen/aic26_ws_speech`；`devel/lib` 下是 catkin 生成的 relay 脚本，
  运行时直接 `exec` `src` 里的源码，**改完重启节点即可，不需要重新 catkin build**
- 接入：`ssh mowen@192.168.1.15`（5 GHz WiFi）
- 显示：车上 `DISPLAY=192.168.1.189:0.0`（Windows 主机），当时 VcXsrv 未启动
- 备份目录：`~/aic26_ws_speech_bak/20261027_162854/`（11 个原文件，按原目录结构）

## 报错记录

- `camera_view`：
  `Gtk-WARNING: cannot open display: 192.168.1.189:0.0`，`exit code 1`（非致命）
- `mission_controller`：
  - 日志停在 `move_base action server is up` 之后**再无输出 3.5 分钟**；
  - 没有 `mission started`，也没有本应 60 s 后出现的 `no map -> base_footprint tf after 60s`；
  - `/cmd_vel` 没有任何 mission 发布的指令，车不动；
  - Ctrl-C 后 14 s 才被 roslaunch 升级为 SIGTERM 强杀，并残留 `PPID=1` 的孤儿进程。
- 复现与取证：
  - `DISPLAY=192.168.1.189:0.0 python3 -c "import tkinter; tkinter.Tk()"` → 15 s 不返回，
    `user 0.02 s`（卡在内核/C 层）；
  - `socket.create_connection(("192.168.1.189", 6000), 5)` → `socket.timeout`
    （**丢包**而不是拒绝连接，所以连接能卡很久）。

## 涉及文件

- `src/aic26_decision/scripts/mission_controller.py`
  - 新增模块级 `_x_display_reachable(timeout=1.0)`；
  - `ResultViewer.start()` 在起线程前先探测，失败只禁用 GUI；
  - 三个调试图订阅从 `ResultViewer.__init__` 移到 `start()`（display 检查通过之后）。
- `src/aic26_perception/scripts/{car,people,traffic_light}_detector.py`

    `rospy.Subscriber(..., queue_size=1)`，停止时 `unregister()`；
  - `publish_debug()` 开头加 `if self.image_pub.get_num_connections() == 0: return`。
- `src/aic26_cobot/scripts/hardware_status_node.py` + `config/status.yaml`
  - 相机存活检测从 `/camera/image_raw`（Image）改为 `/camera/camera_info`（CameraInfo），
    `queue_size=1`，参数名 `image_topic` → `camera_topic`。
- `src/aic26_cobot/scripts/camera_node.py`
  - `image_pub.get_num_connections() == 0` 时跳过 flip / `cv2_to_imgmsg` / 发布；
    CameraInfo 仍按帧率发布。
- 导航参数（同一天另有窄道实验，与本文件无关）：见
  [实车航点雷达坐标语义、膨胀半径与起点朝向容差](2026-10-25_实车航点雷达坐标与膨胀半径调优.md)。

## 修改方案

### 1. GUI 冻结：tkinter 持有 GIL 阻塞整个解释器

- 机制：`tkinter.Tk()` 在 Tcl 的 TCP connect 里阻塞，且**持有 GIL** →
  `mission_controller` 的所有线程（包括主线程的 `wait_ready()`）都无法运行；
  Python 级 SIGINT/SIGTERM handler 也无法执行，所以表现为“卡死 + 杀不掉”。
  `camera_view` 用的是 GTK，会快速报错退出，所以只有它是“干净地死掉”。
- 修复：起线程前用 1 s 超时的 socket 探测 X 端口——本地显示查
  `/tmp/.X11-unix/X<n>`，远程显示连 `6000+n`；探不通就打 warning 禁用 GUI，
  **绝不进 `tkinter.Tk()`**。
- A/B 验证（空任务表，不产生运动）：
  - `_gui:=true` + 坏 DISPLAY → 冻结，连 `timeout 40` 的 SIGTERM 都杀不掉；
  - `_gui:=false` → 0.2 s 内依次打出 `map -> base_footprint tf is up` /
    `mission started` / `mission finished`。

### 2. 图像管线降载

- 背景实测：`/camera/image_raw` 是 1280×720 `bgr8` ≈ **2.76 MB/帧**、约 14.7 Hz，
  有 5 个订阅者（camera_view、hardware_status、3 个检测器）。rospy 在回调**之前**
  就完成反序列化，所以“订阅了但 active=false 直接 return”依然在烧 CPU。
- 措施：
  - 检测器懒订阅（激活才订阅 / 停止即退订）；
  - hardware_status 改用 CameraInfo 做存活检测；
  - 相机在无订阅者时跳过转换与发布；
  - ResultViewer 只在 GUI 真能显示时才订阅三路调试图，检测器也不在无人订阅时绘制/发布。
- 效果（空闲、任务未运行）：

| 指标 | 改前 | 改后 |
|---|---:|---:|
| `camera_node` CPU | 40.6% | 27.5% |
| `hardware_status` CPU | 12.1% | 2.7% |
| 空闲检测器 CPU | 每个 8–9% | ≈0 |
| load average（4 核） | 2.19 | 0.73 |
| `/camera/image_raw` 订阅者 | 5 | **None** |

- 功能验证：`rostopic pub /perception/detect "people"` 后订阅出现、推理 38.5%、
  `/perception/result` 正常输出；发 `"stop"` 后订阅消失；
  `/diagnostics` 的 camera 项为 `ok`（走 camera_info）；
  无头 viewer 打印 `display ... is unreachable, GUI disabled` 后任务正常走完。

## 结果与结论

- 两处修改都已落地并验证：异常 DISPLAY 不再冻结 mission_controller，空闲负载明显下降。
- 行为变化：无头运行（`gui:=false`，或 `gui:=true` 但无显示）时**不再生成**
  `aic26_perception/results` 下的调试图 JPEG；结果 JSON 照常写。
  若比赛需要那些图，需要加一个 `~save_debug_images` 开关（尚未实现）。
- 感知本身（四区 0 人、红绿灯无数据）按用户说明是当前设计如此，本次未改动。
- 附带发现（操作坑）：用 `pkill -f "roslaunch aic26_bringup"` 清理时，
  该模式会**匹配到执行它的 shell 自己**，导致命令被杀、roslaunch 清理不干净，
  留下占着 `/dev/lslidar` 的孤儿节点。正确做法是按 PID 杀，或用括号技巧
  `pkill -f "roslaunch aic26_[b]ringup"`（自己的命令行含方括号，不会被匹配）。
