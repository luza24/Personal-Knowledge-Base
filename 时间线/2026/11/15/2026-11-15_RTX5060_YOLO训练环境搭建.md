# RTX 5060 笔记本 YOLO/CV 训练环境（D 盘 venv）

> 整理日期：2026年11月15日 22:18
> 项目：开发环境 ｜ 类型：环境配置 ｜ 状态：已解决 ｜ 主题：`环境与工具链` ｜ 标签：`python环境`、`yolo`、`opencv`

## 背景 / 目标

需要在这台 Windows 笔记本上同时做 YOLO 训练和 OpenCV 识别，用于 DELI 9011 表盘读数项目。机器有 RTX 5060 Laptop GPU，但现有环境都不能直接训练：

- 当前 base：Python 3.8.15，有 OpenCV/onnxruntime，没有 torch/ultralytics；
- `yolov8` 环境：有 ultralytics 8.4.11、OpenCV、ONNX，但 torch 是 `2.4.1+cpu`，只能用 CPU；
- `pytorvh` 环境：`torch 2.8.0+cu126`，RTX 5060 是 sm_120，cu126 没有对应 kernel，实际矩阵乘报 `no kernel image`。

目标：在 D 盘建一个独立环境，安装支持 Blackwell 的 CUDA 12.8 PyTorch + ultralytics + OpenCV + ONNX，并验证 GPU 真正能训练。

## 报错记录

### 1. cu126 对 RTX 5060 不可用

`pytorvh` 环境：

```text
torch 2.8.0+cu126
torch.cuda.is_available() = True
torch.cuda.get_device_capability(0) = (12, 0)
```

但实际矩阵乘失败：

```text
AcceleratorError: CUDA error: no kernel image is available for execution on the device
NVIDIA GeForce RTX 5060 Laptop GPU with CUDA capability sm_120 is not compatible
with the current PyTorch installation.
The current PyTorch install supports CUDA capabilities sm_61 sm_70 sm_75 sm_80 sm_86 sm_90.
```

结论：只看 `cuda.is_available()` 会误判；必须实际跑一次 CUDA 矩阵乘。RTX 50 系需要 **cu128 或 cu129** 构建，`cu126` 不行。

### 2. conda 的 TLS 失败

默认源和清华 conda 镜像都报：

```text
CondaSSLError: Encountered an SSL error.
HTTPSConnectionPool(host='repo.anaconda.com', port=443):
Max retries exceeded ... SSLError(SSLEOFError(8, 'EOF occurred in violation of protocol'))
```

换成清华镜像后，`mirrors.tuna.tsinghua.edu.cn` 也一样。但同机 `curl` 能正常访问这两个地址，说明是 conda 自带 Python 3.8 的 SSL/代理栈问题，不是网络完全不通。

处理：放弃 conda 建环境，改用现有 Python 3.9 建 **venv**。功能等价、完全隔离，也不影响原有 conda 环境。

## 修改方案

### 1. 建 venv

```bash
py -3.9 -m venv D:/venvs/gauge310
D:/venvs/gauge310/Scripts/python.exe -m pip install --upgrade pip
```

最终 Python 3.9.13，pip 26.0.1。现有 conda 环境一个没动。

### 2. 装 cu128 PyTorch

```bash
D:/venvs/gauge310/Scripts/python.exe -m pip install \
  "torch==2.8.0+cu128" "torchvision==0.23.0+cu128" \
  --index-url https://download.pytorch.org/whl/cu128 \
  --extra-index-url https://mirrors.tuna.tsinghua.edu.cn/pypi/web/simple
```

torch 本体约 3.46 GB（Windows cp39 cu128 轮子），下载约 5 分钟。依赖从清华 PyPI 镜像补。

### 3. 装其余依赖

```bash
D:/venvs/gauge310/Scripts/python.exe -m pip install \
  "numpy==1.26.4" "opencv-python==4.10.0.84" \
  "ultralytics==8.4.11" "onnx==1.17.0" "onnxruntime==1.19.2" \
  pyyaml pillow
```

numpy 固定 1.26.4，避免 numpy 2 与 OpenCV/ultralytics 的 ABI 兼容问题。

## 结果与结论

最终版本：

```text
Python        3.9.13
torch         2.8.0+cu128
torchvision   0.23.0+cu128
CUDA          12.8
ultralytics   8.4.11
opencv-python 4.10.0.84
numpy         1.26.4
onnx          1.17.0
onnxruntime   1.19.2
```

验证结果：

- `torch.cuda.is_available() = True`；
- GPU `NVIDIA GeForce RTX 5060 Laptop GPU`，capability `(12, 0)`；
- CUDA 矩阵乘实际执行成功，没有 `no kernel image`；
- `yolo checks` 全部通过；
- coco8、YOLOv8n、`imgsz=640`、`batch=4`、1 epoch 冒烟训练完成，显存 0.621 GB；
- 权重：`D:\gauge_yolo\runs\smoke\weights\best.pt`；
- D 盘安装后剩约 71 GB。

激活方式：

```bash
# Git Bash
source D:/venvs/gauge310/Scripts/activate
yolo checks

# cmd
D:\venvs\gauge310\Scripts\activate.bat

# 不激活，直接调用
D:/venvs/gauge310/Scripts/python.exe ...
D:/venvs/gauge310/Scripts/yolo.exe ...
```

正式训练建议：

```bash
D:/venvs/gauge310/Scripts/yolo.exe detect train \
  model=yolov8n.pt data=D:/gauge_yolo/dataset.yaml \
  imgsz=960 batch=8 epochs=120 device=0 \
  project=D:/gauge_yolo/runs name=gauge
```

8 GB 显存如果 OOM，降成 `imgsz=640 batch=4`。coco8 在 640/batch4 只用了 0.62 GB，960/batch8 理论上有余量，但仍要实测。

## 注意 / 遗留

- **venv 不是 conda 环境**：conda 的 SSL 问题尚未修；当前 venv 完全可用。若以后必须用 conda，需要先解决 conda 的证书/代理配置。
- **跨盘安装**：C 盘 conda 包缓存不能硬链接到 D 盘；本次用 venv，不存在该问题；pip 缓存仍在 C 盘。
- **路径**：环境、数据、输出都用纯 ASCII；不要把训练数据放中文目录，OpenCV/ultralytics 在 Windows 下可能静默失败。
- **不要混装**：同一环境不要同时装 conda 的 opencv 和 pip 的 opencv-python。
- **无需系统 CUDA Toolkit**：torch wheel 自带运行时，`nvcc` 缺失不影响；不要额外装 `cudatoolkit`。
- **驱动**：592.00 / CUDA 13.1 向后兼容 cu128，不需要升级。
- **许可证**：ultralytics 为 AGPL-3.0，内部使用可以，对外分发需评估。
- **回滚**：删除 `D:\venvs\gauge310` 即可，不影响其他环境；`D:\conda_envs` 空目录可一并删除。
- **数据备份**：D/E 是同一块物理 NVMe 的不同分区，磁盘故障会一起受影响；训练数据、标注、权重仍需另外备份。
