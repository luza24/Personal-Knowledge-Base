# ebike 两站视觉去重与独立去重节点

> 整理日期：2026年11月16日 22:34
> 项目：ROS仿真车 ｜ 类型：功能开发 ｜ 状态：部分解决 ｜ 主题：`感知与视觉`、`导航与运动控制` ｜ 标签：`ros`、`tf`、`perception`、`真车`

## 背景 / 目标

实车在 `ebike_1`、`ebike_2` 两个相邻停车点分别检测同一排电动车。两站各看到约 5 辆，但中间区域重叠：

- 只取一站会漏掉两端的车；
- 直接把两站相加会重复计算中间的车；
- 目标是合并两站结果，输出实际总数和倒伏数。

## 环境信息

| 项 | 值 |
|---|---|
| 实车 | `mowen@192.168.1.15`，`~/aic26_ws_112` |
| 系统 | Ubuntu 20.04，ROS1 Noetic |
| 相机 | 1280×720，`frame_id=camera`，K `fx=fy=640, cx=640, cy=360` |
| 位姿 | `map <- camera_optical_frame`（TF），另有 `/amcl_pose` |
| 任务点 | `ebike_1=(1.1,0.3,yaw 1.5708)`、`ebike_2=(1.1,0.9,yaw 1.5708)`，均 `turn: right` |
| 检测 | `ebike_detector.py`，类别 `down` / `normal` |

## 报错记录

### 1. 区域重叠法少数 1 辆

最初用“两站可见区间的交集”融合，最新 5+5 数据得到 6 辆。原因是把重叠区内基准视图的 4 辆全部当成共享，但其中有一辆只在基准视图可见。

### 2. 点距离匹配多 1 辆

改为底边中心点距离 + 门限后，5+5 得到 8 辆。裁切框 `N 1.152` 和 `N 1.088` 距离只有 0.064 m，被误配。

### 3. 实测输出 `TOTAL=6 method=max_fallback`

实车 2026-11-16 22:01 运行：

```text
ebike_1 total=5 down=2 normal=3 source=complete method=none
ebike_2 total=6 down=3 normal=3 source=complete method=none
ebike dedup: TOTAL=6 DOWN=3 NORMAL=3 | method=max_fallback pairs=0
```

模型检测本身是 5 和 6，但坐标投影全部失败，节点直接取了 `max(5,6)=6`。

## 修改方案

### A. 底边投影 + 区间重叠

对每个检测框 `[x,y,w,h]`：

1. 投影底边左右端点 `(x, y+h)`、`(x+w, y+h)` 到地面 `z=0`，得到 map 下的两端点；
2. 取沿车排方向的区间 `[y0, y1]`；
3. 两站区间重叠度：

```text
inter = max(0, min(y1_a,y1_b) - max(y0_a,y0_b))
ratio = inter / min(len_a, len_b)
```

4. `ratio >= 0.65` 视为同一辆；
5. 一对一贪心，不链式合并；
6. 允许跨类别配对（同一辆车两站可能被分类为 down/normal）；
7. 类别按多数，平票取较早一站；
8. 未配对的点全部保留为独有；
9. 任一点 footprint 无效时回退到单站较大 total，绝不相加。

验证结果：

| 数据 | 单站检测 | 合并结果 |
|---|---|---|
| 最新 20:40 采集 | 5 + 5 | 7 辆 = 4 normal + 3 down，3 对 |
| 旧 20:06 采集 | 5 + 6 | 7 辆 = 4 normal + 3 down，4 对 |

关键阈值：真匹配重叠度均为 1.000；唯一需要拒绝的裁切对为 0.554，因此取 0.65。

### B. 独立去重节点

新增：

- `aic26_perception/scripts/ebike_dedup.py`：纯 numpy/math 的投影和区间合并；
- `aic26_perception/scripts/ebike_dedup_node.py`：独立 ROS 节点。

节点行为：

- 订阅 `/perception/detect`、`/perception/result`、`/camera/camera_info`、`/amcl_pose` 和 TF；
- 只在 ebike 请求期间订阅 camera_info，避免相机常驻 FULL 模式；
- 同一 `run_uuid` 的第二站结果到达后合并，并打印：

```text
ebike dedup: TOTAL=7 DOWN=3 NORMAL=4 (实际 7 辆，倒伏 3 辆) | method=footprint_overlap pairs=3 | ebike_1 total=5 down=2 normal=3 | ebike_2 total=5 down=2 normal=3
```

防丢措施：

- 缓存 5 Hz 的 incomplete 结果；stop 时如果 complete 丢失，用最新 partial 兜底；
- 每站视图写入 `~/.ros/ebike_dedup/*.json`，节点 respawn 后可恢复；
- 只有一站时，30 s 后按 `single_view` 回退；
- 所有异常只 warning，不退出节点。

位姿兜底顺序：

1. TF `map <- camera_optical_frame`；
2. `/amcl_pose` 实际停车位姿 + 固定相机外参；
3. 任务 YAML：读取 `/mission_controller/waypoints_file` 和 `tasks_file`，应用 `frame_correction` 与 `turn`（right 减 90°）；
4. 全部失败才 `max_fallback`。

日志会标明 `method=tf_stamp`、`amcl_pose`、`waypoint_pose` 或 `max_fallback`。

### C. TF 调用签名错误

ROS1 tf 的实际签名：

```python
lookupTransform(target_frame, source_frame, time)   # 只有 3 个参数
waitForTransform(target_frame, source_frame, time, timeout)
```

原实现给 `lookupTransform` 传了第 4 个 `rospy.Duration`，每次抛 `TypeError`，又被 `except` 静默吞掉，导致两站都是 `method=none`。

修复：

```python
if when.to_sec() != 0.0:
    self.listener.waitForTransform(target, source, when,
                                   rospy.Duration(timeout))
trans, quat = self.listener.lookupTransform(target, source, when)
```

同时把 TF 失败原因写入日志，不再静默回退。

### D. 构建与启动

- `aic26_perception/launch/ebike.launch` 增加 `ebike_dedup` 节点，`output="screen"`、`respawn="true"`；
- `CMakeLists.txt` 增加 `ebike_dedup.py`/`ebike_dedup_node.py` 安装和 `tf`、`geometry_msgs` 依赖；
- `package.xml` 增加 `tf`、`geometry_msgs`；
- 不修改 `ebike_detector.py`、`mission_controller.py`、任务 YAML（仅加注释）和语音。

## 结果与结论

- 离线 6 个单元测试通过；
- 生产模块在两组真实 fixture 上均为 **7 辆 / 4 normal / 3 down**；
- 私有 roscore + 静态 TF 验证修复后的 TF 查询：`TF_METHOD tf_stamp`；
- mock 验证 `/amcl_pose` 和 waypoint 兜底均能返回正确外参；
- 更新后的节点在私有 roscore 下能正常启动；
- 实车 22:01 那次 `TOTAL=6` 是 TF 签名 bug 导致的 `max_fallback`，不是合并算法本身。

**待验证**：

- 修复后重新跑一次完整实车任务，确认输出 `method=footprint_overlap` 且总数与现场一致；
- 当前现场预期为 7 辆、倒伏 3 辆，但需以本次实车画面为准；
- 独立节点在第二站检测完成时打印，早于任务 turn_back。

## 任务点修改注意事项

已在 `real_nostrafe_waypoints.yaml` 和 `real_nostrafe_tasks.yaml` 的 ebike 区域加入英文注释，要点：

- `ebike_1`/`ebike_2` 保持同排、同 x，当前间距 0.6 m；
- 两站画面保留约 1.0 m 可见重叠，不能只移动一站；
- waypoint 的 `yaw` 是到达朝向（+y），任务 `turn: right` 后相机朝 +x（yaw ≈ 0）；
- 保持任务名和顺序；改名/重排后要同步 `~fallback_waypoint_names`；
- 修改 YAML 后需重启 dedup 节点才会重新读取缓存。
