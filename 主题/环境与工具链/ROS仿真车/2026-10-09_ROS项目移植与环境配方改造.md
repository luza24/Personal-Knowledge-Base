> 整理日期：2026年10月9日 20:24

## 环境信息

- **本次操作环境（宿主）**：Windows 11 + Git Bash（MSYS）
- **来源容器**：`ros_noetic_gazebo`（`osrf/ros:noetic-desktop-full`），Ubuntu 20.04.6 / ROS1 Noetic / Gazebo 11 / Python 3.8.10
- **代码路径（容器）**：`/root/catkin_ws/src`
- **视觉 venv**：`/root/ylovenv`，**5.32 GB / 25,204 个文件**，含 torch 2.4.1+cu121、torchvision 0.19.1、ultralytics 8.4.166、rapidocr-onnxruntime 1.4.4、onnxruntime 1.19.2、numpy 1.24.4、opencv-python 5.0.0.93

- **目标机器**：同事的**正常 ROS Noetic + Ubuntu 20.04 桌面版**（非 Docker，用户名/路径均不同）
- **仓库**：`github.com/Govis-Ink/aic26.git`，分支 `feature/nav-slam`

## 报错记录

### 1. `docker exec` 路径被 MSYS 静默改写（最先踩的坑）

```
$ docker exec ros_noetic_gazebo du -sh /root/catkin_ws/.venv
du: cannot access 'D:/Git/root/catkin_ws/.venv': No such file or directory
```

**根因**：Git Bash（MSYS）把参数里以 `/` 开头的字符串当成 Unix 路径改写成 Windows 路径。
**危害**：报错里显示一条**看起来像本地 Windows 路径**的路径，极易误判成"容器里这个文件真的不存在"。本次差点据此直接判定 venv 为空。
**解决**：容器相关命令前一律 `export MSYS_NO_PATHCONV=1`（或用双斜杠 `//root/...`）。

### 2. `/root/catkin_ws/.venv` 是个空壳，不是真 venv

```
/root/catkin_ws/.venv/          # 20K, 0 个文件
├── include/                    # 空
└── lib/python3.8/site-packages # 空
```

`git add --dry-run -A .venv` 输出为空——**git 不跟踪空目录，push 上去是零改动**。
历史 commit `fbb90e9` 曾误提交过这个空壳（且不在当前 HEAD 祖先链上）。
项目真正的 venv 是 README 记录的 `/root/ylovenv`。

### 3. `pip freeze` 被 ROS 系统包严重污染

| 命令 | 行数 |
|---|---|
| `pip freeze` | **257** |
| `pip freeze --local` | **58** |

`pip freeze` 多出的约 197 个（`rospy==1.17.4`、`roslaunch`、`rosgraph`、`rqt-*`、`gazebo_ros`、`catkin` 等）来自 `ros.pth` 暴露的 `/opt/ros/noetic/lib/python3/dist-packages`(99 egg-info) 和 `/usr/lib/python3/dist-packages`(117)。**这些包 PyPI 上不存在**，`pip install -r` 会直接 `ERROR: No matching distribution found for rospy==1.17.4`。

### 4. venv 本身不可传

- 5.32 GB / 25,204 文件
- **12 个单文件超过 GitHub 100 MB 硬上限**（最大 `torch/lib/libtorch_cuda.so` 860.6 MB）
- 内嵌绝对路径：`bin/activate` 的 `VIRTUAL_ENV=/root/ylovenv`、`pyvenv.cfg`、`ros.pth`
- 符号链接 `bin/python3 -> /usr/bin/python3`、`lib64 -> lib`，换机断链
- 平台绑定（linux/amd64 + cp38 wheel）

### 5. `GAZEBO_MODEL_PATH` 从未持久化（最隐蔽）

world 文件里 **31 处 `model://` 引用**全靠它解析，但它**不在任何配置文件里**（`.bashrc`/`.profile`/`/etc/environment` 全都没有），只存在于开发者手工 export 的那几个终端。
证据：roslaunch 日志 dump 里有 `'GAZEBO_MODEL_PATH': '/root/catkin_ws/src/aic26_gazebo/models:'`，但新 shell 里为空。另外 `gazebo_ros` 的 `<export><gazebo_ros gazebo_model_path=.../></export>` 在本仓库是**死配置**（`devel/` 下无 env hook）。

### 6. `ros.pth` 是手写的，pip 不会重建（最易漏）

venv 是 `include-system-site-packages=false` 的完全隔离环境，唯一让它能 `import rospy` 的机制是手写的 `ros.pth`（两行裸路径）。
漏了则 `yolo_detector.py` 启动即 `ModuleNotFoundError: No module named 'rospy'`，而且报错发生在 launch-prefix 起的 venv 里，**看起来像 ROS 坏了**。

### 7. `package.xml` 依赖声明严重不全

`aic26_navigation/package.xml` 只声明了 `costmap_2d` + `move_base`，但代码实际用 rospy / std_msgs / nav_msgs / geometry_msgs / std_srvs / gazebo_msgs / actionlib / actionlib_msgs / move_base_msgs，launch 还用 map_server / amcl / dwa_local_planner / global_planner。
→ `rosdep install` 装不全；目标机缺 planner 插件会在运行时报 `Could not find plugin dwa_local_planner/DWAPlannerROS`。
`aic26_slam/package.xml` 缺 `tf2_ros`（gmapping.launch 用了 static_transform_publisher）。

### 8. CRLF 行尾

- **4 个已跟踪文本文件**是 CRLF：`aic26_gazebo/package.xml`、`aic26_gazebo/worlds/aic26-1.world`、`aic26_perception/CMakeLists.txt`、`aic26_perception/package.xml`（此前已存在）
- **`test_image.py` / `test_plate.py` 是 CRLF 且 shebang 是 `#!/usr/bin/env python`（缺 3）** —— 双重问题，容器里 `which python` 为空，直接执行必失败
- 教训：开发机经 Docker 从 Windows 侧编辑极易产生 CRLF，`#!/usr/bin/env python3\r` 在 Linux 上是 `bad interpreter`

### 9. 往文件里写 Markdown 时 Python 转义踩坑

写入 README 时 `\0` / `\n` / `\r` 这类转义序列经 **JSON → shell heredoc → Python 字符串**多层传递后语义发生变化，最终在文件里落下**真实的 NUL(0x00) 和 CR(0x0D) 字节**，`grep` 直接把该文件识别成 "Binary file matches"。
**解决**：改用 **`chr()` 构造**搜索/替换串（如 `chr(92)+"0"` 表示反斜杠+0），源码里不含任何转义序列，彻底消除歧义。定位时用 `open(p,'rb')` 逐字节检查而不是 `grep -c $'\x00'`（bash 里 NUL 会变成空串，匹配全部行，得出误导性的行数）。

## 修改方案

### 1. 依赖清单：只用 `pip freeze --local`

`requirements.txt` 是 9 行精简顶层清单（不是 freeze 输出），`requirements-lock.txt` 由命令生成：

```bash
/root/ylovenv/bin/pip freeze --local | grep -v '^pkg_resources==' > requirements-lock.txt
```

文件顶部注释写明**不要用 `pip freeze` 当清单**及原因。

### 2. `setup_env.sh`：把最易漏的一步自动化

- venv 路径可配（`$1` / `AIC26_VENV`，默认 `$HOME/ylovenv`，与 launch 默认值一致）
- 前置检查：Python 必须 3.8、`/opt/ros/noetic` 必须存在
- **用 `sysconfig.get_paths()["purelib"]` 动态推导 site-packages**，venv 建在任何路径都对
- **写 `ros.pth`**（两行裸路径，硬编码安全：标准 apt 装的 ROS Noetic 就是这两个路径，脚本会校验存在性）
- 末尾 import 自检并打印版本
- 幂等；`--cpu` 分支先装 CPU wheel 再从清单过滤掉 `nvidia-*`/`triton`（PEP 440 下 `2.4.1+cpu` 满足 `torch==2.4.1`，不会二次安装）
- 结尾若 venv 不在默认路径，打印显式的 `python:=` 覆盖命令

### 3. `GAZEBO_MODEL_PATH`：由 launch 自带

在两个 gazebo launch 的 **`<launch>` 顶层**各加一行（不必塞进 `<include>`，roslaunch 的 `<env>` 会沿嵌套传播）：

```xml
<env name="GAZEBO_MODEL_PATH" value="$(find aic26_gazebo)/models:$(optenv GAZEBO_MODEL_PATH /usr/share/gazebo-11/models)"/>
```

⚠️ **roslaunch 不支持替换参数嵌套**：`$(optenv V $(env HOME)/x)` 会报 `ERROR Dollar signs '$' cannot be inside of substitution args`。必须用 `$(optenv VAR 默认值)` 形式避免尾部空段。

### 4. 硬编码路径参数化（7 处）

| 位置 | 改法 |
|---|---|
| `nav.yaml:1` | `image: nav.pgm`（相对路径） |
| 3 个 perception launch 的 `python` | `$(env HOME)/ylovenv/bin/python` |
| 3 个 perception launch 的 `save_dir` | `$(env HOME)/catkin_ws/yolopng` |
| `yolo_save_node.py:31` | `os.path.expanduser('~/catkin_ws/yolopng')` |

`$(env HOME)` 在 `/root` 下解析结果**逐字不变**，本机行为不受影响。

### 5. `package.xml` 补依赖 + 防 CRLF

- `aic26_navigation` 补 rospy / std_msgs / nav_msgs / geometry_msgs / std_srvs / gazebo_msgs / actionlib / actionlib_msgs / move_base_msgs / map_server / amcl / dwa_local_planner / global_planner，加 `rviz`、`python3-matplotlib`
- `aic26_slam` 补 rospy / tf2_ros，加 `rviz`
- `.gitattributes` 加 `* text=auto eol=lf` 后一次性 `git add --renormalize .`

### 两条被反汇编/实测确证的关键结论

1. **ROS1 noetic 的 `map_server` 会把相对 `image:` 解析到 yaml 所在目录**（与 cwd 无关）。
   依据：`nm -D -u map_server` 只导入 3 个 boost::filesystem 符号（`parent_path` / `root_directory` / `operator/=`），`objdump -d -C` 证明三处调用全部落在 `MapServer::loadMapFromYaml` 函数体内；再用 `cd /` 实测确认。
2. **`map_saver` 会把 `-f` 参数原样写进 yaml 的 `image` 字段**（不导入任何 boost::filesystem 符号），这就是 `nav.yaml` 变成绝对路径的成因。且 roslaunch 节点 cwd 默认是 `~/.ros`、`<node cwd>` 只接受 `ROS_HOME`/`node`，**无法靠 launch 绕过**，只能用 `fix_map_yaml.sh` 后处理。
