# AI 生产力框架报告：从会用、会搭到会选

> 整理日期：2026年11月01日 19:39

## 背景 / 目标

用户大二，已能用 Claude Code（接 DeepSeek）+ 中转站使用 GPT，但"对 AI 生产力一直不了解"。需求明确不是工具推荐清单，而是一张**可反复追问的框架地图**——先建整体结构，再按节深挖。

约束（经提问确认）：

- 场景优先级：编程开发 > 学术科研/读论文 > 学习与信息管理
- 深度：会用 → 会搭 → 会选，三层递进
- 投入：愿意深入，但需要清晰路径与检查点，不接受自己瞎摸

## 核心论点（全文脊柱）

> **AI 的能力边界 = 任务的「好」能不能被写成文字。**
> 写不出来 → 只能用 AI 草稿；写出来 → 剩下的是上下文与验收。

对应软件工程里的 TDD：先写好测试，代码写对就不再靠运气。三条失灵点贯穿全文——会用层解决单次任务（任务拆解 / 上下文 / 验收）、会搭层解决重复任务（接入形态 / 上下文供给 / 停止条件）、会选层解决选型错误（能力四维 / 结构性做不到 / 成本与隐私）。

## 关键结论

- 三类幻觉中**风格幻觉最危险**：格式专业、内容空洞，专骗不熟悉该领域的人；对策是「名词抽取法」——把每句的名词/数字/因果单独拎出来问依据。
- 任务四分类：搬运型 ★★★★★（放心用，抽查中段）／生成型 ★★★★☆（先写验收）／判断型 ★★☆☆☆（会讨好，必须反着问）／探索型 ★★☆☆☆（会编来源）。
- Agent 跑飞的真实原因排序：没验证器 > 停止条件模糊 > 工具报错差 > 上下文膨胀 > 模型能力。
- 用户现有工具分工：Claude Code + DeepSeek 当施工队；中转站 + GPT 当「唱反调的人」——对抗式双模型，不同训练分布的错误不相关。
- 本地模型对个人基本不值得，仅四条件之一成立才考虑（数据不能出本机 / 调用量极大 / 需离线 / 需微调）。
- 中转站三个默认假设：会留存数据、关键路径会断、可能模型偷换（用指纹题定期测）。
