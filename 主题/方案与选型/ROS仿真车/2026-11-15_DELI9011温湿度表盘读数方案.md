# DELI 9011 温湿度表盘双指针读数方案（实车 meter 航点）

> 整理日期：2026年11月15日 22:18
> 项目：ROS仿真车 ｜ 类型：方案选型 ｜ 状态：进行中 ｜ 主题：`感知与视觉`、`方案与选型` ｜ 标签：`ros`、`yolo`、`opencv`、`perception`、`真车`

## 背景 / 目标

要在巡检实车的 `meter` 航点读取 DELI 9011 温湿度计的两根独立指针：

- 温度：`-30 ~ 50 °C`，长针；
- 湿度：`0 ~ 100 %RH`，短针；
- 精度目标约 `0.5`（按 `0.5 °C / 0.5 %RH` 设计）；
- 相机装在车上，每次停车角度有小幅变化，且画面像素较低、可能模糊。

用户提供了角度映射表，并找到两个 GitHub 项目希望直接复用。本次完成了项目评估、角度约定校正、纯 CV 测量方案设计，以及实车 `aic26_ws_112` 的接入规划。当前尚未写测量代码，也还没有 `meter` 点实拍图；状态为进行中。

## 关键校正：映射表是 y-up 数学坐标

用户给的映射表：

```text
temperature:
  327.5: 50, 358.7: 40, 30.2: 30, 61.6: 20, 93.1: 10,
  123.2: 0, 152.0: -10, 180.0: -20, 207.2: -30

humidity:
  136.5: 100, 151.4: 90, 171.8: 80, 196.9: 70,
  223.2: 60, 248.4: 50, 276.4: 40, 305.2: 30,
  334.8: 20, 6.2: 10, 44.0: 0
```

一开始把它当成图像坐标 `atan2(dy, dx)`（y 向下）来用，长针被读成约 50 °C。核对表盘数字位置后确认：

- 映射表实际是**数学坐标：y 轴向上、逆时针为正**；
- 图像坐标 `φ = atan2(dy, dx)`（y 向下）与表角 `θ` 的关系是 `φ = (360 - θ) mod 360`；
- 样图正确读数是**温度约 29.3 °C、湿度约 19.0 %RH**，长针指在 30 附近，不是 50。

这个方向如果搞反，温度会系统性偏约 20 °C，因此实现时必须先写单测锁定：样图 → 29.3 °C / 19.0 %RH。

两个量程在图像里都是顺时针扫过：温度约 239.7°（-30→50），湿度约 267.5°（0→100）。映射表的角度约有 ±6° 人工估计噪声，只能当先验，最终映射要用每帧检测到的刻度锚点。

## 仓库评估

| 项目 | 方案 | 现成权重 | 许可证 | 结论 |
|---|---|---|---|---|
| `Jason-Shell/gauge-ai-reader` | Python + YOLOv8-Pose，每盘 4 关键点（min/max/tip/center），角度比例 + 径向精修，ONNX/TFLite | WIKA 双刻度压力表（bar/psi） | 无 License | 架构可参考；必须重训；代码不能直接复用 |
| `zhahoi/Nanodet-YoloV8-Pose-MeterReader` | C++/ncnn，Nanodet 找 ROI + YOLOv8-Pose 取关键点 | 某款压力表 | Apache-2.0 | 代码写死 `/home/hit/...` 和 MPa 偏移，数据集在百度网盘，不适合直接使用 |

最终决定：**YOLOv8n 只负责检测整块表的 ROI，不输出角度；刻度、指针、读数由自写 OpenCV 完成。** 这样标注成本低、测量可解释，也不依赖姿态关键点的针尖精度。

## 方案设计

### 1. 总体流水线

```text
停车 → YOLO 找整块表 → 椭圆/仿射校正
     → 双轮毂、旋转 δ、刻度锚点
     → 温度长针 / 湿度短针角度
     → 角度映射 → 多帧融合 → 状态码 → JSON
```

### 2. 定位与旋转自适应

- 大圆：限定安装 ROI 内 `HoughCircles`，用圆周梯度覆盖率和圆内灰度校验；
- 小湿度盘：按“大圆心→小圆心”的固定相对向量搜索，不全局扫描；
- 轮毂：圆心附近找深色 blob 精修；
- 旋转：`δ = wrap180(φ(小圆心-大圆心) - φ_ref)`，另用刻度弧最大缺口做第二估计；两者差 >2~3° 降置信度；
- **任何环节都不用绝对图像角度**，读数通过当前帧检测到的刻度锚点得到。

### 3. 刻度与指针

- 黑帽 `MORPH_BLACKHAT(11×11)` + 极坐标展开（0.25° 角分辨率）；
- 温度刻度环 `r∈[0.68, 0.84]R`，湿度环 `r∈[0.62, 0.90]R_s`；
- 主刻度用径向长度区分，最大缺口两端即 min/max（温度 -30/50，湿度 0/100）；
- 指针用径向暗度积分（±1.5 px 法向取最大、减角向基线），取前 5 峰；
- 每个候选做 `fitLine`/RANSAC：过轮毂（距离 <3 px）、径向支撑 >0.5 倍针长、残差 <1.2 px；
- 5 点抛物线亚像素，多帧圆周中位数；
- 温度长针只在有效刻度弧 ±8° 搜索，湿度短针只在小盘内。

### 4. 多帧与异常

- 停车后连拍 1.5~2.0 s，1080p@10 fps；按 Laplacian + 刻度高频能量选 4~5 帧；
- 帧间角度离散 >1° 标 `LOW_CONFIDENCE`，不强行平均；
- 状态码：`OK / LOW_CONFIDENCE / DIAL_NOT_FOUND / SCALE_MISMATCH / NEEDLE_OCCLUDED / OUT_OF_RANGE / GLARE / MOTION_BLUR`；
- 失败也发 `complete=true`，避免 mission 等待超时。

## 精度与像素门禁

精度换算：

- 温度：`239.7° / 80°C = 2.996°/°C`，`0.5°C = 1.50°`；
- 湿度：`267.5° / 100%RH = 2.675°/%RH`，`0.5%RH = 1.34°`。

1080p、90° 水平视场下 `fx≈960 px`，表盘像素直径约 `pixel = fx * D / distance`：

| 距离 | 大盘 100 mm | 小湿度盘 35 mm |
|---:|---:|---:|
| 0.30 m | 320 px | 112 px |
| 0.25 m | 384 px | 134 px |
| 0.20 m | 480 px | 168 px |
| 0.15 m | 640 px | 224 px |

门禁阈值：

- 大表盘刻度环直径 ≥ **360 px**（推荐 450~600）；
- 小湿度盘刻度环直径 ≥ **180 px**（推荐 220+）；
- 按上表，当前 1080p + 90° 镜头 + 约 10 cm 表盘，相机需要离表约 **0.15~0.24 m**，否则 0.5 %RH 物理上不可达。

这是头号风险。软件放大不会增加信息；只能把 `meter` 航点改近、加近摄/变焦镜头或更高分辨率相机，或放宽湿度精度。**第一步必须用 1~3 张 meter 点 1920×1080 原图量出大/小刻度环像素直径，再决定是否继续。**

## 训练与数据

- 在 meter 点采集 200~400 张 1080p 原图：约 10 个会话 × 30 帧，停车位置 ±5 cm、角度 ±5°，覆盖模糊、反光、部分出画；
- 只标 1 类 `gauge`，框住整块表；按会话划分 train/val（80/20），避免相邻帧泄漏；
- 在 Windows RTX 5060 上训练 YOLOv8n，`imgsz` 优先 960（表盘小则 1280），120 epochs；
- 验收：按会话的 val 集召回 ≥98%、误检率 <1%；
- 导出 ONNX `opset=12, dynamic=False, simplify=True`，不要在导出时内置 NMS；
- 拷到实车 `models/gauge_det.onnx`，用 OpenVINO/onnxruntime 推理；车上不装 PyTorch；
- 若 1080p 下表框仍 <80 px，改为先裁固定 meter ROI 再训练/检测。

## 结果与结论

- 两个 GitHub 项目都不能直接用于 DELI 9011：权重对应别的表，且一个无 License、一个 C++/ncnn 且硬编码；
- 方案确定为 **YOLOv8n ROI + OpenCV 测角 + 刻度锚点校准**；
- 角度约定已校正：映射表是 y-up 数学坐标，样图应为 **29.3 °C / 19.0 %RH**；
- 实车接入点、协议、文件改动和数据/训练流程已梳理；
- Windows 训练环境已就绪（RTX 5060 + torch 2.8.0+cu128 + ultralytics 8.4.11）；
- **当前未完成**：meter 点实拍图、像素门禁、`gauge_reader.py` 实现、数据标注与模型训练、实车集成测试。

下一步：

1. 发 1~3 张 meter 点 1920×1080 原图，量大/小刻度环像素；
2. 门禁通过后先写 `gauge_reader.py`，用样图单测锁定 29.3 °C / 19.0 %RH；
3. 再采数据、训练 YOLOv8n、导出 ONNX；
4. 最后改 `meter` 任务和 mission 播报/结果，实车单节点 + 整车验证。
