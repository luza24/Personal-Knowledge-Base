# 实车 bringup 双相机预览可靠性（RGB + 红外等待占位）

> 整理日期：2026年11月23日 21:51
> 项目：ROS仿真车 ｜ 类型：功能开发 ｜ 状态：部分解决 ｜ 主题：`感知与视觉`、`硬件与调试` ｜ 标签：`ros`、`真车`、`x11`

## 背景 / 目标

希望每次执行：

```bash
roslaunch aic26_bringup bringup.launch backend:=real
```

都能同时看到 RGB `camera` 窗口和 `IR thermal` 红外窗口。

实际经常“摄像头打不开 / 红外没画面”。排查后确认预览节点本身已经默认启动，问题集中在设备与显示层：

- station 上位机抓过一次图后会独占 `/dev/video0` 约 60 秒（`server.py` 的 `Camera.IDLE=60`），`stop.sh` 不等待设备释放；
- HIK 红外 `2bdf:0101` 未枚举时，`ir_camera` 只每 10 秒报错，`ir_view` 窗口一直空白且没有任何提示；
- 从普通 SSH 终端启动时 `DISPLAY` 为空，`camera_view` / `ir_view` 在 `cv2.namedWindow` 失败后直接退出；
- `bringup.launch` 没有 `ir_view` 参数，传 `ir_view:=false` 会被忽略。

目标：自动停 station、恢复 Orbbec UVC、等待 HIK、IR 无画面时显示可见占位；入口仍用 roslaunch，不新增一键脚本。

**硬件边界**：HIK 没枚举属于 USB/供电问题，软件无法让不存在的设备出现；方案只能做到等待、提示，并在插上后自动出图。

## 环境信息

| 项 | 值 |
|---|---|
| 实车 | `mowen@192.168.1.15`，N100 4 核 / 7.5 GB |
| 工作区 | `~/aic26_ws_112` |
| RGB | Orbbec DaBai DCW2，`2bc5:0561`，稳定路径 `/dev/v4l/by-id/usb-Sonix...Orbbec...-video-index0` |
| 红外 | HIK HikCamera，`2bdf:0101`（当时未枚举） |
| 显示 | NoMachine，`DISPLAY=:1001`；普通 SSH 会话 `DISPLAY` 为空 |
| station | `~/rc/station/server.py`，Web 8780 |

## 现状与关键代码

- `backend.launch` 在 `backend=real`、`show_view=true` 时 include `camera_view.launch`。
- `aic26_bringup/mission.launch` 在 `backend=real` 时 include `ir.launch`，`ir_view` 默认 true 并 include `ir_view.launch`。
- `camera_node.py` 默认 `device_name=Orbbec`、index 0、autodetect：优先 by-id，`_matches()` 会拒绝 HIK 节点，因此 HIK 占用 video0 时仍能找到 Orbbec；无需改设备选择逻辑。
- `ir_camera_node.py` 用 sysfs 名含 `hik` 且 index 0（备选 by-id）查找，`retry_interval=2s`、`warmup_timeout=300s`；设备缺失时只报错不退出，且只有存在订阅者时才尝试打开。
- `camera_view.py` 之前没有帧时从不 `imshow`，也没有超时提示，所以 IR 窗口是一块空白。
- `scripts/pre_run_clean.py` 已有 `scan_processes()`、`device_holders()`、`usb_devices()`、`rebind_orbbec()`；`scripts/preflight_vision.py` 有 `_reattach_uvc()`；两者 main 都有 `__main__` 保护，可安全 import。

## 修改方案

### 1. 新增 `vision_preflight.py`

文件：`src/aic26_cobot/scripts/vision_preflight.py`，由 `backend.launch` 的 real 组启动（`output="screen"`，不 respawn）。

启动后按顺序：

1. 检查 `DISPLAY`；为空或 `/tmp/.X11-unix/X<n>` 不存在时 `logerr`，提示从 NoMachine 终端启动或 `export DISPLAY=:1001 XAUTHORITY=/home/mowen/.Xauthority`。
2. 用 `pre_run_clean.scan_processes()` 找 `rc/station/server.py`（不依赖 `station.pid`），执行 `~/rc/station/stop.sh`，再对残留 PID 发 SIGTERM，5 秒内不退则 SIGKILL；然后等 `/dev/video0..3` 的 holder 清空（默认 10 秒）。
3. 用 `rebind_orbbec()` 检查 Orbbec 接口是否都绑定 `uvcvideo`；不是则发 `USBDEVFS_CONNECT 0xC0105512`（接口 0/1），2 秒后复查；打印 by-id 路径。
4. 轮询 HIK `2bdf:0101` 与 sysfs 里 `hik` capture 节点，默认最多 120 秒；每 10 秒提示插拔；若 dmesg 在最后一次 HIK 枚举后出现 `uvcvideo ... -71`，提示需要断电 10 秒以上（软件 reset 无效）。
5. 打印汇总后 `rospy.spin()` 保持存活，避免 roslaunch 报 `process has died`。

关键日志：

```text
vision_preflight: stopping station (pid 114542)
vision_preflight: video devices released
vision_preflight: Orbbec RGB ok: /dev/v4l/by-id/usb-Sonix...-video-index0
vision_preflight: HIK 2bdf:0101 not enumerated, unplug/replug the IR USB (waiting up to 120s)
vision_preflight: done (rgb=ok ir=missing display=check station=stopped)
```

### 2. 预览窗口占位

文件：`src/aic26_utils/scripts/camera_view.py`（已有 `draw_text()` 和 numpy）。

新增参数：

- `~waiting_text`：无画面时显示，`|` 分隔多行；
- `~no_frame_timeout`：超过多少秒无新帧显示占位，默认 2.0，0 关闭。

无帧或超时后生成同尺寸黑色图，显示窗口名、等待文字、`no signal Ns`、`q: quit`；收到新帧自动恢复。使用 OpenCV 英文字体，避免中文字模问题。

launch：

- `camera_view.launch` 增加 `waiting_text`（默认 `waiting for camera image`）与 `no_frame_timeout`；
- `ir_view.launch` 传入 `waiting_text="IR camera|HIK 2bdf:0101"`。

### 3. launch 接入

- `src/aic26_bringup/launch/backend.launch`：real 组、hardware include 之前加入 `vision_preflight` 节点，参数 `station_stop`、`ir_wait=120`、`video_wait=10`。
- `src/aic26_bringup/launch/bringup.launch`：新增 `<arg name="ir_view" default="true"/>`，并在 mission include 中转发；`mission.launch` 原本已有该参数。
- `src/aic26_cobot/CMakeLists.txt`：`catkin_install_python` 列表加入 `scripts/vision_preflight.py`。

## 验证

- 远端 `python3 -m py_compile` 通过；`catkin_make` 返回 0；`CATKIN_WHITELIST_PACKAGES` 已清空。
- `roslaunch aic26_bringup bringup.launch backend:=real --nodes` 包含 `/vision_preflight`、`/camera`、`/camera_view`、`/ir_camera`、`/ir_view`；加 `ir_view:=false` 后 `/ir_view` 消失。
- `--dump-params` 确认 `waiting_text`、`no_frame_timeout`、`vision_preflight` 参数均生效。
- 单独运行预检节点：
  - 启动 station 后运行，预检成功停掉 station（输出“上位机已停止”）；
  - Orbbec 识别为 by-id；
  - 无 HIK 时按预期等待并报错，不阻塞；
  - `DISPLAY` 为空时明确提示。
- 占位绘制单测：270×360 黑图 + 多行文字生成正常。
- **未执行完整 bringup**（会启动导航/任务），因此真实窗口显示与拔插 HIK 恢复未在实机验证。

编译过程中遇到一个坑：`catkin_make --pkg aic26_cobot aic26_utils` 只把最后一个包写进 `CATKIN_WHITELIST_PACKAGES`，导致 `make aic26_cobot/all` 找不到目标。正确做法：

```bash
catkin_make -DCATKIN_WHITELIST_PACKAGES="aic26_cobot;aic26_utils"
# 或显式单包
catkin_make -DCATKIN_WHITELIST_PACKAGES="aic26_cobot"
# 最后清空白名单
catkin_make -DCATKIN_WHITELIST_PACKAGES=""
```

## 结果与结论

- 预览链路现在具备：自动停 station、Orbbec UVC 重绑、HIK 等待与明确提示、IR 空白窗口占位、`ir_view` 开关。
- HIK 缺失时 bringup 不会卡死；IR 窗口显示 `IR camera / HIK 2bdf:0101 / no signal Ns`，插上并枚举后自动出图。
- **待验证/遗留**：
  1. 完整 bringup 下两路窗口的真实显示（需要在 NoMachine 终端跑）；
  2. 物理拔插 HIK 后 `ir_camera` 首帧（40–45 秒）与占位切换；
  3. 当前运行的 `dual_camera_view.launch` 栈会占用 `/dev/video0`，预检会提示但不会杀它；启动 bringup 前应先停掉；
  4. 如果工作区后续把红外改成串口模块（`serial_ir_camera_node.py`），`vision_preflight` 里的 `2bdf:0101`/`hik` 判断需要同步替换或关闭。
