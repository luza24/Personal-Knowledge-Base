# 实车八类报告行与终端过滤

> 整理日期：2026年11月25日 07:22
> 项目：ROS仿真车 ｜ 类型：功能开发 ｜ 状态：部分解决 ｜ 主题：`感知与视觉`、`语音与交互` ｜ 标签：`ros`、`perception`、`真车`

## 背景 / 目标

实车 `bringup.launch backend:=real` 下所有 `output="screen"` 节点都会往终端打日志，任务报告被淹没。用户要求终端只保留八类任务结果：

1. 人偶数量；
2. 指示牌；
3. 垃圾桶；
4. 楼宇火灾；
5. 异常温度；
6. 站房仪表；
7. 车辆车牌；
8. 电动车。

其余日志不显示；语音播报保持原样。最终采用 **正常 bringup + `[REPORT]` 固定前缀 + grep 过滤** 的方式，不改 bringup 的启动方式。

## 终端报告格式

### 垃圾桶 + sort

四类垃圾桶按 `recyclable / other / harmful / kitchen` 顺序各输出一条：

```text
可回收垃圾桶状态为关闭，垃圾桶里垃圾为烟头，投放错误。
其他垃圾桶状态为关闭，垃圾桶里垃圾为无，投放正确。
有害垃圾桶状态为关闭，垃圾桶里垃圾为无，投放正确。
厨余垃圾桶状态为关闭，垃圾桶里垃圾为无，投放正确。
```

- 实现：`mission_common.py` 的 `format_bin_terminal_lines()`；
- 每个 sort 项按归一化 x 中心落到桶的 x 区间，否则归最近桶中心；
- 一个桶多个垃圾用 `、` 连接；
- 桶内无垃圾时写 `无`，并判 `正确`。

### 电动车汇总

在 `ebike_pano` 识别结束后打印一次：

```text
A街区有2辆电动车违停，B街区无违停，停车区内电动车正常4辆，倒伏2辆。
```

- A/B 违停数来自各人员点 `ebike_park` 的逐点累加；
- 正常/倒伏来自 `ebike_pano` 的 `normal` / `down`；
- 无违停写 `A街区无违停`；
- 实现：`mission_common.py` 的 `format_ebike_terminal_summary()` 与 `mission_controller.py` 的 `_emit_ebike_summary()`。

### 仪表

```text
温度表读数为30度。湿度表读数为54%。电表读数为235.1kWh
```

- 温度/湿度缺失写 `--`；
- 电表带 `kWh` 单位；缺失写 `--`；
- 实现：`format_gauge_terminal_message()`。

### 车辆车牌

三个停车点各输出一次：

```text
1号停车场车牌号为鄂A12345
```

- 无车牌、无车或 `total<=0` 时写 `x号停车场车牌号为--`；
- 停车点名字无法解析出编号时不输出；
- 实现：`format_car_terminal_message()` 与 `_car_spot()`。

### 其余四类

| 类别 | 输出条件 |
|---|---|
| 人偶数量 | 六个人工点汇总后输出一次 `社区内共有 ...` |
| 指示牌 | `sign_gate` 的 `blocked` 分支与 `passable` 分支的 sign 二次检测都输出 `前方是禁止直行指示牌。`；`passable` 的「未检测到标志牌，此路可通行。」仍只播报 |
| 楼宇火灾 | 检出火灾隐患时输出 `...发现火灾隐患N个` |
| 异常温度 | 正常与异常都输出；无异常时输出 `未发现异常温度。` |

这些都通过 `_report_line()` 输出，不再只写 node log。

## `[REPORT]` 标记与过滤

`mission_controller.py` 增加：

```python
REPORT_PREFIX = '[REPORT] '

def _report_line(self, text):
    text = str(text or '').strip()
    if text:
        print(REPORT_PREFIX + text, flush=True)
```

所有八类报告改为 `_report_line(...)`。`report_grep.sh` 负责过滤：

```bash
roslaunch aic26_bringup bringup.launch backend:=real "$@" 2>&1 | \
    grep --line-buffered -F '[REPORT]' | \
    sed -u 's/.*\[REPORT\] //'
```

启动方式：

```bash
~/aic26_ws_112/report_grep.sh
```

## 旁路脚本的结论

曾尝试 `report_terminal.py` / `report_terminal.sh`：同时抓 roslaunch stdout 和 mission node log，不改 mission 也能显示八类报告。实际遇到两个问题：

1. 旧版脚本用 `start_new_session=True` 启动 roslaunch，脚本/终端退出后 roslaunch 变成孤儿继续跑，但没有进程再打印报告；
2. ResultViewer 的 Tk 窗口关闭会触发 `mission_controller.on_close()` 的 `rospy.signal_shutdown('result viewer closed')`，任务直接中止（exit code 120）。

因此旁路脚本已不作为推荐路径；车上如果还留着旧的 `report_terminal.sh`，不要再用。正常 bringup 时也**不要关闭 ResultViewer 窗口**。

- 新增终端格式化测试共 25 个，连同现有 `test_ebike_speech.py`（9）、`test_gauge_meter.py`（6）等，决策包共 **40 个测试通过**；
- `mission_controller.py` / `mission_common.py` 通过 `py_compile`；
- 车牌用例覆盖了“无车但有旧车牌”时必须输出 `--` 的情况；
