# AIC26 垃圾分类 sort 模型替换与 rubbish bin 自动检测接入

> 整理日期：2026年11月15日 19:21
> 项目：ROS仿真车 ｜ 类型：功能开发 ｜ 状态：部分解决 ｜ 主题：`感知与视觉` `硬件与调试` ｜ 标签：`ros` `yolo` `openvino` `perception` `真车`

## 背景 / 目标

实车 `aic26_ws_112` 的 vision 部分要把 `sort.onnx` 换成 2026-11-15 新训练的模型，并在
mission 的 **rubbish bin** 停靠点自动做垃圾分类检测。

排查后发现一个关键前提：工作区里**没有 sort 检测节点/launch/任务**，`sort.onnx` 只被手动工具
`detect_gui.py --target sort` 使用；rubbish bin 任务实际跑的是 `rubbish_detector.py` +
`rubbish.onnx`（8 类垃圾桶开/关盖）。因此本次工作分为三块：

1. 替换 `models/sort.onnx`；
2. 新增 ROS sort 检测节点，并在 rubbish bin 任务里与 rubbish 顺序检测；
3. 把 sort 置信度从 0.25 调到 0.75，并建立电脑端批量图片测试。

## 报错记录

### 1. 日志里的 `signal-15` 不是外部杀节点

早期独立跑 sort.launch 时，节点日志里出现大量 `signal_shutdown [signal-15]`，一度怀疑是
外部 SIGTERM。用 `strace -f -e trace=signal` 跟踪后定位：

```text
28490 kill(28499, SIGTERM) = 0
28499 --- SIGTERM {si_pid=28490, si_uid=1000} ---
```

28490 是 sort 主进程，28499 是 OpenVINO 启动时 fork 的辅助进程；主进程在初始化结束后主动
`kill()` 清理这些辅助进程。辅助进程继承了同一个 ROS 日志文件，所以看起来像“节点被外部杀掉”。
主节点在干净环境下注册正常，`rosnode list`、`/perception/detect` 订阅和检测请求都正常。

> 教训：这类独立测试失败时先检查是否有残留的旧进程/多个 ROS master；本机 `pgrep -f`
> 也可能把 OpenVINO 的线程/子进程算进去。

### 2. sort 模型 opset 18 的加载验证

新模型是 opset 18 / IR 8（旧模型 opset 12 / IR 7）。实车 OpenVINO 2024.4 和
onnxruntime 1.19 都能加载；若将来换更老的 OpenVINO，需要在 `perception_common.YoloNet`
的 OpenVINO 分支失败后回落 onnxruntime，或重新导出 opset 12。

## 修改方案

### 1. 模型替换与元数据

新 `sort.onnx`：

- md5 `a705c906a18f1eecd68d653aba881b04`，44,782,475 B
- 输入 `[1,3,640,640]`，输出 `[1,28,8400]`（4 + 24 类）
- 24 类名称/顺序与现有 `SORT_CLASSES` 完全一致（bread … waste_roll）
- 训练时间 2026-11-15 11:33，opset 18 / IR 8

旧模型 md5 `84c65af2…`，已保留备份。替换后 `detect_gui.py` 不需要改类别表，直接生效。

### 2. `sort_detector.py`

以 `ebike_detector.py` 为模板，保持其它检测器一致的 v2 行为：

- 24 类 `CLASSES`；`conf` 默认 0.75、`nms` 0.45；
- 首帧开启观察窗口，`observe_time=0.8 s`、`min_frames=2`，空结果 `empty_observe_time=0.5 s`；
- 按帧统计每个类别的框数，窗口结束取总框数的众数帧，只发一次 `complete=true`；
- 结果字段：`total`、`counts`（类名→数量）、`present`、`max_conf`、`boxes`、
  `frames`、`observe_s`、`frame_counts`、`selected_frame`；
- 只在请求期间订阅 `/camera/image_raw`，其它 target 请求时自动关闭；
- debug 图 `/perception/sort/image`；protocol `/perception/sort/protocol`（latched + 1 Hz 重发）；
- 模型加载失败直接 `RuntimeError`，避免“空结果”被当正常；
- 使用正常 1280×720，不请求 rubbish 检测器的 1080p 切换（`detect_gui` 验证时也是 720p）。

### 3. 任务与播报接入

`rubbish bin` 任务改为：

```yaml
  - name: "rubbish bin"
    type: inspect
    waypoint: "rubbish bin"
    turn: "left"
    dwell: 1.5
    targets: ["rubbish", "sort"]
    messages:
      rubbish: "Rubbish bin inspection finished."
      sort: "Sorting inspection finished."
```

`mission_common.format_result_message` 增加 sort 分支，按数量降序输出分类明细，例如：

```text
检测到垃圾共 3 件：塑料瓶 2 件，菜叶 1 件。
```

`mission_controller.build_message` 把 `rubbish` 和 `sort` 都纳入 `messages` 兜底；
ResultViewer 增加 sort 图、summary 段和分类列表；`known` 白名单加入 `sort`，让协议门禁
（`protocol_wait`）覆盖新节点。

### 4. 启动时序

- `protocol_wait` 从 10 s 增至 20 s，给第 9 个 44 MB fp32 模型的 OpenVINO 编译留时间；
- sort 节点 `node_delay = task_delay + 6.0`，与 fire 的 +3 s 错开，避免 9 个模型同时编译。

### 5. 置信度调整

原 sort 置信度 **0.25**，三处同步改为 **0.75**：

- `launch/sort.launch` 的 `conf`
- `detect_gui.py` 的 `TARGETS['sort']['conf']`
- `sort_detector.py` 的 `~conf` 默认值

修改前备份为 `*.bak_20261115_conf075`，不需要 `catkin_make`，重启节点/bringup 生效。
`roslaunch --dump-params` 已确认 `/sort_detector/conf: 0.75`。

## 验证

### 1. 模型加载与单图推理

- 实车 `YoloNet` 用 OpenVINO 加载成功，`size=640`，24 类；
- 用 2026-11-14 的垃圾桶照片离线跑，识别出
  `plastic_bottle / vegetable_leaf / medicine_tablet` 共 3 件，最高分 0.845。

### 2. ROS 联调（不占用相机）

用静态图片发布 `/camera/image_raw`，发 v2 请求，确认：

- `detect subscribers`、`image subscribers` 均为 1；
- `/perception/result` 返回 `target=sort`、`complete=true`、`total=3`、`counts`、
  `boxes`、`selected_frame=2`；
- `/perception/sort/image` 能收到标注图；
- 测试退出码 0。

### 3. 电脑端 96 张图批量测试

在 `C:\Users\luza\_sort_batch_test` 下复制实车的 `sort.onnx` 和 `perception_common.py`，
安装 onnxruntime 1.17.3，用 `test_sort_batch.py` 对
`C:\Users\luza\Desktop\photo2\photo` 的 96 张 1280×720 图片批量推理。单组约 8 秒。

| 置信度 | 检出总数 | 有检出图片 | 最低分 |
|---|---|---|---|
| 0.25 | 366 | 96/96 | 0.319 |
| 0.50 | 357 | 96/96 | 0.502 |
| 0.60 | 347 | 96/96 | 0.614 |
| **0.75** | **335** | **96/96** | **0.769** |

结论：

- 0.75 下 96 张图仍有检出，24 类没有一类完全消失；
- 相比 0.25 少 31 个框，集中在 28 张图各少 1–2 个低分框；
- 典型例子：`photo_20261108_210827_03.jpg` 左侧被画面裁掉的红桶，`paint 0.68` 被过滤，
  其余 `shell 0.95 / fruit_core 0.94 / can 0.98` 保留；
- 若现场更看重“只露一半的桶”，0.6 是折中（347 个、最低分 0.614）。

### 4. 备份清理

工作区 `.bak` 从 99 个（43.9 MB）清理到 55 个（43.57 MB）：

- 只删除 2026-11-13 之前的 44 个旧备份，约 0.36 MB；
- 旧 `sort.onnx`、两份地图备份、11-13 起全部备份（含 `_sort` / `_paddle`）保留；
- 删除前打包到工作区外：
  `/home/mowen/aic26_backup_archive_20261115_pre1113.tar.gz`（64 KB，含清单）。
