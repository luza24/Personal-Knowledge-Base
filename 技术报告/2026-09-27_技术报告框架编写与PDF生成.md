# 技术报告框架编写与 PDF 生成

> 整理日期：2026年9月27日 21:38

## 环境信息
- 操作系统：Windows 11 Home China 10.0.26200（Shell: Git Bash / mingw64）
- Python：3.8.15（另有 3.13.14、conda 多环境）
- 关键库：PyMuPDF (fitz) 1.24.11、markdown 3.7、python-docx 1.1.2
- 可用工具：pdftotext（mingw64 自带），无 pandoc、无 poppler-utils
- 中文字体：微软雅黑 msyh.ttc、黑体 simhei.ttf 等均存在于 `C:/Windows/Fonts/`

## 报错记录
1. **PDF 中文乱码**：`pdftotext -layout` 提取《技术报告.pdf》与《26智慧社区.pdf》时，中文正文全部变成方块/乱码（模板 PDF 只能提取到英文、目录页码和少量结构）。原因是两份 PDF 内嵌字体缺 Unicode 映射（ToUnicode CMap 缺失）。
2. **Read 工具无法读 PDF**：`Read` 直接读 PDF 返回 `[Unsupported Document]`；指定 `pages` 参数报 `pdftoppm is not installed`。
3. **渲染图片读不了**：用 `pix.save()` 渲染成 PNG/JPG 后，`Read` 读图返回 `[Unsupported Image]`（本环境图片通道不可用）。
4. **乱码无法反向还原**：尝试 `get_text()` 结果用 `latin-1`/`cp1252`/`cp437` 编码后再 `gb18030` 解码，全部失败（字符不在对应编码表内），证明不是简单的编码反转问题。
5. **控制台 GBK 编码报错**：验证脚本 `print()` 含 `•`(U+2022) 等字符时抛 `UnicodeEncodeError: 'gbk' codec can't encode`（Windows 控制台默认 GBK，与 PDF 本身无关）。
6. **markdown 表格未渲染成真表格**：表格行因缩进 2 空格（作为列表子项）或紧跟标题无空行，被 markdown 库当作文本而非 `<table>`，PDF 里显示成字面 `|...|`。
7. **Word 文件占用导致写入失败**：用 python-docx 生成 docx 时抛 `PermissionError: [Errno 13] Permission denied: 'C:\\Users\\luza\\Desktop\\技术报告框架.docx'`。原因是目标文档已在 Word 中打开（桌面存在 `~$技术报告框架.docx` 锁文件），无法覆盖。解决办法：改用带 `_v2` 后缀的新文件名输出，避开被占用文件。

## 修改方案
1. **PDF 内容解析**：中文提取失败后，改用「乱码文本中的结构信息 + 已知代码」反推语义——从英文关键词（YOLOv10n、PaddleOCR、move_base、gmapping 等）、目录页码、`srv` 定义片段还原模板结构；比赛题目靠渲染图失败后，从乱码里仍可读出的数字/分值（红绿灯10、人群12、车牌12、站牌仪表14 等）重建评分细则。
2. **markdown → PDF**：用 PyMuPDF 的 `fitz.Story` API（HTML→PDF），配合 `fitz.DocumentWriter` 分页，`paper_rect("a4")` 设定页面，页边距约 1.8cm。
3. **emoji 处理**：PDF 里 emoji 会变方块，转换前把 `✅🟢→√`、`🟡→△`、`🔴→×`、`⚠️→※` 替换为 CJK 安全符号。
4. **表格修复**：表格代码块前补空行、去掉列表缩进，使 `tables` 扩展正确生成 `<table>`。
5. **编码兜底**：验证 PDF 用「写入 UTF-8 文件再 Read」代替 `print()`，规避控制台 GBK 报错。
6. **Word 文档生成**：用 python-docx 1.1.2 生成，`_set_run` 通过 `w:eastAsia` 设置中文字体（黑体标题/宋体正文），`WD_ALIGN_PARAGRAPH` 居中，`Table Grid` 风格 + `Cm()` 设置列宽。
7. **章节结构对齐去年报告**：将框架从「按任务拆解」改为去年报告的骨架——引言 1.2 改为「核心挑战与解决思路」（1.2.1 环境配置与模型建立 / 1.2.2 运动控制与路径规划 / 1.2.3 视觉部署与识别实现 / 1.2.4 稳定性保障与拓展性开发）；第 3 章核心模块统一采用「功能描述 / 算法原理实现方法 / 难点与对策」三段式，并补上 3.2 软件核心框架与开发环境；新增 3.6 红绿灯时序控制模块；新增第 4 章「硬件选型与 Sim2Real 部署」（赛题硬性要求），测试/总结顺延为第 5、6 章。
