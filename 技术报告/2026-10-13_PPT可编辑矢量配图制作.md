## 报错记录

### 一、几何/排序类

1. **组深度参数写串，排序静默失效**（拐角图，最隐蔽的一个）
   - 现象：三辆车里唯独**相机盒完全看不见**，底盘顶面把相机盖住了。
   - 根因：`add_box()` 算出 `gdep`（长方体中心深度）后调用 `sc.add(..., grp=gdep)`，但 `Scene.add()` 的形参是 `grp`、存的却是自己另一个形参 `gdep`（默认 `None` → 退回"图元自身深度"）。等于**组深度根本没生效**，排序退化成逐面深度；底盘顶面质心深度恰大于相机盒，于是后画、盖了上去。
   - 教训：同一概念在两个函数里用了两个名字，Python 不报错，结果静默错。**统一成一个参数名**后正常。

2. **越界图元把 group 包围盒撑出页面**
   - 现象：走廊色带为了"延伸到画外"给的多边形远超画布，导致整个 `grpSp` 的 `off_y = -660736 EMU`、`ext_cy` 比页面还高，选中框跑到幻灯片外。
   - 解法：加了 **Sutherland–Hodgman 矩形裁剪**（`clip_polygon`），对打了 `clip` 标记的图元按最终画布 bbox 裁掉。

3. **逐行画圆画成了方块**
   - 现象：合成红绿灯场景里点亮的红灯是**方块**；跑完 HSV 后掩膜也是个方块，一眼假。
   - 根因：`d.line([(lx-R, y), (lx+R, y)])` 每行都画满宽，再叠一个椭圆描边 → 只有描边是圆的，填充是方的。
   - 解法：每行按半宽 `sqrt(R² - (y-cy)²)` 收窄。修完掩膜面积 7856 px ≈ π·50²，正好是灯盘。

4. **H 通道渲染成彩色雪花**
   - 现象：把 HSV 的 H 通道直接上色画出来，暗背景是**满屏彩色噪点**，完全没法看。
   - 根因：**近黑像素带 ±2.8 噪声后**，`(max-min)/max*255` 算出的**饱和度反而很高**（如 `(12,14,10)` → S=73），只按 `S < 60` 置灰挡不住。
   - 解法：改成 `(S > 60) & (V > 60)` 才显示色相，其余用明度灰。并在图里标注"低饱和 / 过暗像素置灰"，不隐瞒处理。

### 二、版面类

5. **时间轴刻度落进泳道**
   - 现象：时序图底部刻度 `0.0 / 0.5 / …` 全跑进"视觉节点"泳道里，和推理带的文字叠在一起。
   - 根因：`axis()` 里 y 写的是**相对卡片的常量**，却漏加了卡片原点 `cy0`；同一函数里 x 用的是绝对坐标，所以只有 y 错。
   - 解法：函数签名补 `cy0`。**教训：一个函数里混用相对/绝对坐标，必错。**

6. **括号位置错误 → 列表里混进 float**
   - 报错：`TypeError: cannot unpack non-iterable float object`（在 `for a, b in it['pts']`）
   - 根因：`D.LN([(cx0+X(T0+0.05), AXIS_Y), (cx0+X(T1)), AXIS_Y], …)` —— 第二个元素**括号提前闭合**，列表变成 `[元组, float, float]`。
   - 教训：构造点列表时，长表达式里的括号配对要数清楚。

7. **卡内图片高度算漏，压到说明文字上**
   - 现象：2×3 图里第 1、2、4 格的图片下边越过分隔线，和第 4 格说明文字 `H∈[0,179] …` 叠在一起。
   - 根因：`IMG_H = CH - 0.50 - 0.78` 手算的两个减数不对应当前的 `HEAD_DIV` / `CAP_DIV`。
   - 解法：改成从显式常量推导 —— `IMG_H = CH - IMG_TOP - CAP_DIV - 0.05`，并让 `hue_axis()` 复用同一个 `IMG_TOP`。

8. **标签叠字 / 标签压带**（时序图，两处）
   - `发布检测请求` 与 `继续巡逻·不等待` 都放在泳道上方，居中框宽度重叠 → 一个挪到线下方。
   - `响应` 放在 `c1 + 0.14`，正好落进 `阻塞等待` 带（带占 `c1±0.27`）→ 挪到带下方 `c1 + 0.36`。

9. **图太宽装不进右半栏**
   - 用户反馈"太大了，我的图就放在 ppt 右半部分"。原图按整页做 12.2 × 7.8；16:9 幻灯片右半栏是 **6.67 × 7.5（竖长）**。
   - 解法：**改成四泳道共用一条时间轴的单卡竖版**（6.6 × 6.7），四条泳道上下叠，比对反而更准。

### 三、工具链类

10. **PPTX 被 WPS 占用**：`PermissionError: [Errno 13] Permission denied`
    - 现场：桌面有 `~$图_..._可编辑.pptx` 锁文件 + `wpp.exe` 在跑。
    - 处理：先输出到 `_imgwork/_new.pptx` 验证，稍后 `cp` 覆盖即成功（**锁是陈旧的**）。**不要贸然杀 WPS 进程**，用户可能正开着。

11. **PowerPoint COM 报 `被呼叫方拒绝接收呼叫`**（`RPC_E_CALL_REJECTED`，`-2147418111`）
    - 现象：`Dispatch` 成功，第一次真实调用就抛。
    - 根因：PowerPoint 还在启动/忙。
    - 解法：**加重试循环**（25 次 × 1.5 s），逐调用重试而不是只重试 Dispatch。

12. **等宽字体会让中文变方框**：代码块把字体从 `微软雅黑` 换成 `Consolas` 后，`# 阻塞直到返回` 渲染成一串方框。→ **代码块只放 ASCII**。

13. **`✗ / ✓` 字符可能缺字**：改用矢量线自绘（`tick()` 折线 / `cross()` 两笔画），不吃字体。

14. **`build_freeform` 的坐标精度**：局部坐标传 `round(屏幕单位 × 20000)`、`scale = EMU/20000`，逐图元回读偏差 ≤ 63 EMU（0.005 pt，纯量化误差）。**验证时别把容差设成 3 EMU**，那是自找误报。

## 修改方案

### 一、通用做法（三张图共用）

1. **一份几何/图元数据源 → 多个渲染器**。图元统一成 `rect / poly / tri / line / text / img` 六种（`figdsl.py`），左边距单位一律**英寸**，线宽 **pt**。同一份列表分别喂给 Pillow（出 PNG 预览）和 python-pptx（出可编辑 PPTX）。
2. **PPTX 全部是 PowerPoint 原生形状**：多边形走 `shapes.build_freeform()` + `add_line_segments()` + `convert_to_shape()`；虚线用 `line.dash_style = MSO_LINE_DASH_STYLE.DASH`；文字用 `add_textbox`。
3. **压掉主题阴影**：每个形状都设 `shape.shadow.inherit = False`，否则会继承 Office 主题投影。
4. **整体打包成一个组**：python-pptx 没有 group API，手工拼 `<p:grpSp>` 并把子形状挪进去，取 **恒等变换**（`off == chOff`、`ext == chExt`），子形状坐标就不用改。
5. **验证必做两件事**：(a) 回读 PPTX 逐图元比对 bbox；(b) **用 PowerPoint COM 真的导出一张 PNG 看**。本次三张图都跑了，实渲结果与设计稿一致。

### 二、拐角原地转向图（文书创新点配图）

- **视角**：轴测，方位角 −45°、仰角 47°。取这个方位角有个好处——**世界 XY 平面内的圆恰好映成轴对齐椭圆**（`rx = r, ry = sin(e)·r`），地面阴影和转向圆弧不用旋转矩阵。
- **布局**：A 左上（驶向拐角）→ B 拐角顶点（离观察者最近、视觉焦点）→ C 右上（驶离）；A/B 为低饱和浅灰蓝虚线幽灵车，C 为实色车。
- **车形按用户给的真车渲染图重做**：从图上采样出 `底盘顶面 #0404ff / 侧面 #00008c / 轮子 #252525 / 相机紫 #6d04b2 / 雷达盘纯黑`，做成方形箱体 + 四个明显外凸的大麦轮（轮面加 45° 滚轮刻线）+ 紫色小长方体相机 + 细杆托黑圆盘雷达。作图时把底盘饱和度**略压**成 `#2A2AE6`，免得在一片浅灰蓝里太刺眼。
- **闭环验证**：先用 Pillow 出预览自检，再用 PowerPoint COM 实渲核对。

### 三、HSV 红绿灯检测原理图（2×3 六格）

- **不是画的，是真跑出来的**：用 `aic107/aic26_perception/scripts/vision_utils.py` 里 `tl_state_hsv` 的**原逻辑**（`S>90 & V>90` 掩膜 → 掩膜内饱和度最大像素的色相 → `H≤12 或 ≥168 红 / ≤55 黄 / ≤110 绿`）跑合成场景，六格分别是：原图 → YOLO 检测框 → 裁剪 → **H/S/V 三通道** → 发光掩膜 → 色相阈值带。
- 图里所有数字都是真实计算结果：检测框 **600×170 px**、发光像素 **7856 px（占裁剪 7.7%）**、最纯像素 **H = 3 → 红灯**。
- **红绿灯外形按用户给的真车截图重做**：横排三灯头（红-绿-黄）、双立柱、黑路面 + 白色斑马线 + 棕色墙。第一版做成竖排三灯被否。
- 第 6 格是纯矢量的**色相轴**：五段色带（红/黄/绿/灰/红）+ 阈值刻度 + 实测 H 标记。

### 四、ROS 服务同步检测时序图

- **论点定位**：光画流程图说不清"异步为什么一定错位"，必须画**时序对比**。查了真实代码 —— `YoloClient` 三个方法都只做 `resp = self.proxy()`，底层 `rospy.ServiceProxy('/yolo/detect', Trigger)`，**这行代码本身就是论点**（服务代理调用在收到响应前不返回）。
- **最终形态（按用户要求从整页改到右半栏）**：单卡竖版 6.6 × 6.7 in，**四泳道共用一条时间轴** —— 上组「传统：话题异步订阅」两条泳道，下组「本方案：服务同步调用」两条。四条泳道共享同一刻度，上下天然对齐。
- 关键视觉：下半组用**两条灰色虚线**把主控的"阻塞等待"带和视觉的"推理 0.3~1.0 s"带框在同一区间，配绿字 `阻塞区间 ≡ 推理区间`——这就是"不可能错位"的证据。
- 卡内代码按真实代码写，且**只放 ASCII**：`sub = rospy.Subscriber('/yolo/detections', String, cb)` / `resp = self.proxy()   # blocks until reply`。
