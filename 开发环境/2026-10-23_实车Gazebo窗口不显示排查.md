# 实车 Gazebo 窗口不显示排查（Remote-SSH + VcXsrv X11 转发）

> 整理日期：2026年10月23日 15:20
> 项目：开发环境 ｜ 状态：已解决 ｜ 标签：`报错排查` `ros` `gazebo` `x11` `真车`

## 背景 / 目标

通过 VS Code Remote-SSH 连到实车 `mowen@192.168.1.15`，在车上 `aic26_ws` 里执行
`roslaunch aic26_bringup bringup.launch mode:=mission backend:=sim`，仿真能跑起来，
但 Windows 桌面上没有 Gazebo GUI 窗口。目标是定位原因并让窗口显示出来。

## 环境信息

- 车端：Ubuntu + ROS noetic（Gazebo classic 11），工作区 `/home/mowen/aic26_ws`
- 车端主机名 `mowen-JNE10`，无本地图形会话（无 Xorg、无 `/tmp/.X11-unix`）
- 访问方式：Windows 11 + VS Code Remote-SSH（1.142.0），集成终端 `XDG_SESSION_TYPE=tty`
- Windows 侧 X server：VcXsrv `:0`（端口 6000），车端可访问 `192.168.1.189:6000`

## 报错记录

**现象**：launch 正常启动，`gzserver` 一直在跑，但看不到 Gazebo 窗口。

关键证据：

- roslaunch 拉起 gzclient 的环境里没有 `DISPLAY`，`XDG_SESSION_TYPE=tty`
- `~/.ros/log/latest/roslaunch-mowen-JNE10-400017.log:290`：
  ```
  [gazebo_gui-3] process has died [pid 400290, exit code 134, cmd .../gzclient --verbose ...]
  ```
  启动 3 秒后 SIGABRT —— Qt 连不上 X display 的典型表现
- `rosout.log` 中 mission_controller 记录：
  ```
  result viewer: no display (no display name and no $DISPLAY environment variable), GUI disabled
  ```
  RViz、camera_view 窗口同样因此没有出现
- 车端 `DISPLAY=192.168.1.189:0 xdpyinfo` 报：
  ```
  Authorization required, but no authorization protocol specified
  ```
  （VcXsrv 未带 `-ac`，默认只允许本机客户端）
- 车端无本地 X server：`/tmp/.X11-unix` 为空、无 Xorg/gnome-shell 进程

## 涉及文件

- `~/aic26_ws/src/aic26_gazebo/launch/sim.launch`（只读排查）：对 `empty_world.launch` 写死 `gui=true`，
  所以无论是否需要显示都会拉起 gzclient
- `~/aic26_ws/src/aic26_bringup/launch/bringup.launch`、`mission.launch`、`backend.launch`（只读排查）：
  `gui` 参数只传给 `aic26_decision` 的任务 GUI，**不控制 Gazebo 窗口**，`gui:=false` 关不掉 Gazebo
- Windows：VcXsrv 启动参数（唯一实际改动，未改任何代码）

## 修改方案

### 方案 A（采用）：VcXsrv 带 `-ac` + 显式 DISPLAY

1. 重启 Windows 侧 VcXsrv，关闭访问控制：
   ```
   "C:\Program Files\VcXsrv\vcxsrv.exe" :0 -multiwindow -clipboard -wgl -ac
   ```
   用 XLaunch 时对应勾选 **Disable access control**，Display number 固定 0。
2. VS Code 集成终端（Remote-SSH 不转发 X11，只能显式指定 Windows 的 IP）：
   ```bash
   export DISPLAY=192.168.1.189:0        # IP 为 DHCP，先用 ipconfig 确认
   roslaunch aic26_bringup bringup.launch mode:=mission backend:=sim
   ```

### 方案 B（备选，不改 VcXsrv）：另开 Git Bash 用 ssh X11 转发

```bash
export DISPLAY=127.0.0.1:0
ssh -Y mowen@192.168.1.15
cd ~/aic26_ws && source devel/setup.bash
roslaunch aic26_bringup bringup.launch mode:=mission backend:=sim
```

- 必须 `-Y`。本机 Git Bash 没有 xauth，`-X` 报
  `untrusted X11 forwarding setup failed: xauth key data not generated`；
  `-Y` 使用 fake auth 可正常转发，远端 `DISPLAY=mowen-JNE10:10.0`
- VS Code 集成终端做不到这一点，必须在单独的 ssh 会话里跑 roslaunch

## 结果与结论

已解决。方案 A 实测验证：

- `DISPLAY=192.168.1.189:0 xdpyinfo` 正常返回，vendor `HC-Consult`（VcXsrv）
- 带 DISPLAY 起 bringup 后 `gzclient` 进程存活，`xwininfo -root -tree` 可见
  `"Gazebo" ("gazebo" "gazebo") 1138x542` 和 `"navigation.rviz - RViz"` 窗口
- 验证用的 roslaunch/gzserver/gzclient/rviz 已全部停止，ROS master 已释放

注意事项：

- Windows 的 WiFi IP 是 DHCP（当天为 `192.168.1.189`），换网/重连后要重新确认
- VcXsrv 必须保持运行；`-ac` 期间同网段任何机器都能无认证连 6000 端口（能显示窗口、读键盘/剪贴板），
  不想放宽可另起 `:1` 实例给自己用，别人的 `:0` 不受影响
- 想纯无头运行需改 `sim.launch`，launch 参数关不掉 Gazebo GUI
