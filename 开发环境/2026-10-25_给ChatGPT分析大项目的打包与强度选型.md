# 把大型 ROS 项目交给 ChatGPT 分析：打包与推理强度选型

> 整理日期：2026年10月25日 12:15
> 项目：开发环境 ｜ 状态：已解决 ｜ 标签：`方案选型` `chatgpt` `ros`

## 背景 / 目标

要把 21 MB 的 aic1023（aic26_* 10 个 ROS1 包）交给 ChatGPT 做代码分析，需要先决定两件事：

1. 用哪个模型、哪个推理强度；
2. 怎么把工程喂进去——直接拖整个目录会把 20 MB 的 onnx 模型和 Gazebo 贴图/网格也算进去。

目标：生成一个体积小、信息全、模型能直接读的上传包，并配一套分轮提示词。

## 环境信息

- 宿主：Windows 11，miniconda（Python 3.8）
- ChatGPT 订阅：Pro（2026-10）
- 2026-10 选择器：Chat 里选 GPT-6（由 Sol 驱动），强度有 Medium/High；Pro 档额外有 Extra High 和 Pro（底层 Astra）
- 本地工具：无 `zip` 命令，用 Python `zipfile` 打包；`unzip` 校验
- 目标工程：`C:\Users\luza\Desktop\aic1023`

## 报错记录

- **JSON/heredoc 转义吃反斜杠**：把 Python 脚本直接写在 Bash heredoc 里，`C:\\Users\\...` 经 JSON 解码后变成 `C:\Users`，Python 报 `unicodeescape truncated \UXXXXXXXX escape`。改为把脚本写到临时 `.py` 文件再执行。
- **目录规则漏报被跳过的资产**：第一版只统计扩展名黑名单，`meshes/`、`results/` 里的文件因为目录被跳过而没有计入「未包含」清单，manifest 少报了约 2.4 MB。改为先遍历全集再分类（included / excluded / skipped），并在 `_PROJECT_MAP.md` 里分组列出。
- **树形图重复一层**：按包分组渲染时把包名打印了两次。改成一次渲染整个相对路径树，根节点写 `aic1023/`。

## 修改方案

### 1. 模型与强度选型

| 阶段 | 模型 | 强度 | 理由 |
|---|---|---|---|
| 建图 / 架构 / 逐模块 | GPT-6 | High | 5.7k 行、10 个包，需要跨文件多跳推理 |
| 风险与找 bug | GPT-6 | Extra High（Pro 可再开 Pro/Astra） | 收益最高的一轮，值得加档 |
| 不建议 | — | ultra / max / Deep Research | 文本只有 393 KB，上下文完全放得下；瓶颈在推理链长度，不在搜索空间；Deep Research 是联网找资料的，不读代码库 |

要点：**effort 不改变读到的内容，只改变每一步的推演深度**。低档省时间，代价是跨文件矛盾容易被放过。

### 2. 打包：只保留文本源码与配置

- 保留：`.py .cpp .h .hpp .launch .sdf .world .xacro .urdf .yaml .yml .xml .json .msg .txt .md .config .material .rviz .sh`
- 排除：`*.onnx *.dae *.stl *.jpg *.jpeg *.png *.pyc *.bag`，以及 `__pycache__/`、`results/`、`meshes/`
- 结果：159 个文件 / 392.5 KB；zip 压缩后 155.6 KB
- zip 根部自动生成 `_PROJECT_MAP.md`：目录树、各包文件数/代码行数、未包含的二进制清单（含 3 个 onnx 与资产目录）、`package.xml` 依赖汇总

这样做的目的：既不让模型臆测 onnx 网络结构，也避免上传 20 MB 无用二进制。

### 3. 校验

```bash
unzip -t aic1023_chatgpt_src.zip          # 完整性
unzip -l aic1023_chatgpt_src.zip | tail -1 # 160 entries
unzip -l ... | grep -Eic '\.(onnx|dae|stl|jpe?g|png|pyc|bag)$'  # 必须为 0
# 逐条比对 zip 条目与源目录，确认 159 个条目都有对应源文件
```

实测：160 个条目（159 源文件 + `_PROJECT_MAP.md`）、二进制扩展名命中 0、全部条目可映射回源目录。

### 4. 提示词分轮

`aic1023_chatgpt_prompts.md` 里包含：

1. 探针消息：先确认模型真的读到文件，再开始分析；
2. 全局规则：结论必须带 `文件:行号`、无法确认写「未确认」、不要反问；
3. Round 0 建图 → Round 1 数据流 → Round 2 模块深挖 → Round 3 风险清单（Extra High）→ Round 4 总结；
4. 追问与校准：行号对不上时让它重定位；关键结论要求它自己找反例；
5. 读不了 zip 时的退路：解压后分 3 批上传，或改用 Codex 指向本地目录。

## 结果与结论

- 上传包与提示词手册均已生成并校验通过，**原 `aic1023` 目录未做任何改动**。
- 后续用户选择直接在当前会话里完成审查（high 做架构、xhigh 做风险清单），ChatGPT 包保留作为备份/交叉验证手段。
- 经验：给 LLM 分析工程时，**先按扩展名做文本/二进制分层**比直接上传目录可靠得多；manifest 要显式列出「存在但未提供」的资产，能显著减少模型臆测。
