# E 盘清理与 C 盘瘦身：旧 Docker 数据识别与数据搬迁

> 整理日期：2026年10月15日 19:43
> 项目：开发环境 ｜ 状态：部分解决 ｜ 标签：`部署迁移` `docker` `wsl2` `claude-code` `python环境`

## 背景 / 目标

C 盘（系统盘，642GB）只剩 64.8GB，E 盘（80GB）几乎占满却全是垃圾。目标是清空 E 盘并把 C 盘的大文件搬过去，缓解系统盘压力。用户最初的想法是把 E 盘这 80GB 直接并给 C 或 D（改分区），实测后因风险否决。

## 环境信息

- 操作系统：Windows 11 Home China 10.0.26200，单块 NVMe（SAMSUNG MZVL81T0HELB-00BTW，953.9GB，GPT）
- Docker Desktop：WSL2 后端，`CustomWslDistroDir` 已指向 `C:\DockerData\DockerDesktopWSL`
- WSL 发行版：`Ubuntu`、`Ubuntu-20.04`、`docker-desktop`（均 Stopped）
- Steam：主程序 `D:\steam\steam.exe`，库配置 `D:\steam\steamapps\libraryfolders.vdf`

## 报错记录

1. **`Clear-RecycleBin -DriveLetter E -Force -Confirm:$false` 报「系统找不到指定的文件夹 / FailedToClearRecycleBin」** —— 但回收站其实已清空，属虚报。
2. **`pip cache purge` 只释放约 1GB** —— 报 `Files removed: 119`，但 `AppData\Local\pip\cache\http-v2` 里仍留 19.25GB。
3. **清 Temp 导致命令输出丢失** —— 执行「清理 Temp」的那条 Bash 调用返回 `output file could not be read (ENOENT)`，因为 Claude Code 的输出文件就在 `%LOCALAPPDATA%\Temp\claude\...` 下，被同一条命令删掉了。

## 涉及文件

- `E:\DockerData\DockerDesktopWSL\disk\docker_data.vhdx` —— 75.37GB（9/23 迁移后遗留的旧副本）【删】
- `E:\DockerData\DockerDesktopWSL\main\ext4.vhdx` —— 108MB（同上）【删】
- `E:\docker` —— 空目录【删】
- `E:\$RECYCLE.BIN` —— 4.15GB（ubuntu-20.04.4 ISO、zip/exe/pdf、openmv-ide 等）【清空】
- `C:\Users\luza\AppData\Local\Temp\*` —— 11.2GB【清空】
- `C:\$Recycle.Bin` —— 10.2GB【清空】
- `C:\Users\luza\AppData\Local\pip\cache\http-v2\*` —— 19.25GB【删】
- `C:\SteamLibrary` —— 59.6GB → 迁至 `E:\SteamLibrary`（残留 604MB 未清）
- `C:\Users\luza\xwechat_files` —— 16GB → 迁至 `E:\xwechat_files`
- `C:\Users\luza\AppData\Roaming\Docker\settings-store.json` —— 当前 `CustomWslDistroDir = C:\DockerData\...`；`.bak`（9/23）为 `E:\DockerData\...`【只读，用于取证】

## 修改方案

### 1. 判定 E 盘旧 Docker 数据可删（四条证据）

单纯「复制到 C 盘」不足以下结论，须确认 E 盘那份已无任何引用：

- 旧配置 `settings-store.json.bak`(9/23) 的 `CustomWslDistroDir` 指向 `E:\DockerData\...`，当前配置(10/14)已改为 `C:\DockerData\...`
- WSL 注册表 `HKCU:\Software\Microsoft\Windows\CurrentVersion\Lxss`：`docker-desktop` → `C:\DockerData\...`；`Ubuntu`/`Ubuntu-20.04` → `C:\Users\luza\AppData\Local\wsl\{GUID}` —— **三个发行版无一引用 E 盘**
- C 盘 vhdx 当天仍在写，E 盘那份停在 9/23 16:29
- E 盘 vhdx 是真实文件（`LinkType` 为空），非符号链接/硬链接

### 2. 否决「删 E 分区并给 C/D」的方案

实测分区布局（按 offset 排序）：

```
[1 EFI 0.3G] [3 C: 642.2G] [2 MSR] [4 Recovery 1.2G] [5 E: 80G] [6 D: 200G] [7 RESTORE 28G] [8 Recovery 0.3G]
```

即 **C → Recovery → E → D**，E 夹在中间。删 E 后的未分配空间既不在 C 右侧、也不在 D 右侧，**Windows 自带磁盘管理无法扩展任何一方**；要并给 C 还得挪/删 Recovery 分区并移动系统盘（高风险），并给 D 则需第三方工具搬动 D 上约 116GB 数据（中风险）。故全部否决，改走「清空 E + 搬迁」的零风险路线。

### 3. 三步执行

```powershell
# 阶段 1：清空 E 盘（执行前确认 WSL 三发行版均 Stopped）
Remove-Item -Path 'E:\DockerData' -Recurse -Force
Remove-Item -Path 'E:\docker' -Recurse -Force
Clear-RecycleBin -DriveLetter E -Force -Confirm:$false

# 阶段 2：清理 C 盘缓存
python -m pip cache purge
Remove-Item "$env:LOCALAPPDATA\Temp\*" -Recurse -Force -ErrorAction SilentlyContinue
Clear-RecycleBin -DriveLetter C -Force -Confirm:$false
# pip 不彻底，需补一刀：
Remove-Item 'C:\Users\luza\AppData\Local\pip\cache\http-v2\*' -Recurse -Force
```

阶段 3 走 GUI 官方机制（无命令）：Steam `设置 → 存储空间 → 移动` 到 `E:\SteamLibrary`；微信 `设置 → 文件管理 → 更改` 到 `E:\xwechat_files`。

## 结果与结论

- **E 盘**：可用 0.1GB → 79.7GB（清空）→ 4.6GB（搬入 Steam 59.05GB + 微信 16.02GB）
- **C 盘**：可用 62.4GB → **178.3GB**（净 +115.9GB）
- 搬迁校验：`E:\SteamLibrary` 三个游戏（DAVE THE DIVER、Don't Starve Together、PUBG）、`E:\xwechat_files` 均就位；微信旧位置已清空
- **遗留 1**：`C:\SteamLibrary` 残留 604MB（CS:GO 社区自定义内容），已确认无 `.acf` 清单、Steam 不再管理；且 `libraryfolders.vdf` 仍挂 `C:\SteamLibrary` 条目，`E:\SteamLibrary` 重复出现两次 —— 建议在 Steam 存储设置里移除该库位置
- **遗留 2**：未做 Docker 回归验证（启动 Docker 跑 `docker images`/`docker ps -a` 确认 C 盘那份 75.5GB 数据完好）—— E 盘旧副本已删，这是唯一一份
