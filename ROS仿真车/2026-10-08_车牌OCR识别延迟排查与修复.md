# 车牌 OCR 识别延迟 5-6 秒排查与修复

> 整理日期：2026年10月8日 20:55

## 环境信息
- 宿主：Windows 11 家庭中文版 + Docker Desktop（Git Bash 环境）
- 容器：`ros_noetic_gazebo`（镜像 `osrf/ros:noetic-desktop-full`），ROS Noetic
- 工作区：`/root/catkin_ws`（构建工具 `catkin_make`，纯 Python 包，devel 脚本为 relay wrapper 直接 exec 源码）
- 视觉运行环境：独立 venv `/root/ylovenv`（cv2、numpy、torch、ultralytics、rapidocr_onnxruntime，经 `ros.pth` 接入 ROS）
- 代码结构（本次排查时容器已重构）：
  - `scripts/yolo_detector.py` —— 服务式检测节点，车牌 OCR 的唯一执行者（模糊匹配版）
  - `scripts/vision_utils.py` —— 公共模块，含 `_get_ocr()`、`read_plate()`、`match_plate()` 等
  - `scripts/yolo_save_node.py` —— 已改为只订阅 `/yolo/annotated_image` 存图，不推理、不加载 OCR

## 报错记录
- **现象**：巡逻过程中，小车识别到车牌时，终端约 **5-6 秒后才输出车牌字符**（`检测结果: {...}` 与 `plates` 数组迟迟不出）。
- **触发条件**：进程启动后**第一次**检测到车牌（`cls_id == 3`）时；之后再次识别则很快。

## 涉及文件
- 容器 `/root/catkin_ws/src/aic26_perception/scripts/yolo_detector.py` —— 本次实际修改文件
- 本地 `C:\Users\luza\Desktop\aic107\aic26_perception\scripts\yolo_detector.py` —— 同步同样改动（与容器一致）
- 未改：`yolo_save_node.py`（容器里已不加载模型）、`vision_utils.py`（`_get_ocr` 本身无需改）

## 修改方案
1. **根因定位**：`vision_utils.py` 中 OCR 采用**懒加载**：
   ```python
   _ocr = None
   def _get_ocr():
       global _ocr
       if _ocr is None:
           from rapidocr_onnxruntime import RapidOCR
           _ocr = RapidOCR()   # 首次才初始化，加载 det/rec/cls 三个 ONNX 模型，CPU 上 3~6 秒
       return _ocr
   ```
   调用链：`yolo_detector.py` 检出车牌 → `read_plate()` → `_plate_text(_ocr_items(...))` → `_get_ocr()` 首次触发 `RapidOCR()` 冷启动，阻塞整个 `/yolo/detect` 服务 5-6 秒，期间终端无输出。
2. **修复**：把冷启动**提前到节点启动阶段**，在 `YoloDetector.__init__` 加载完 `YOLO(weights)` 后，新增可选预加载：
   ```python
   self.preload_ocr = rospy.get_param('~preload_ocr', True)
   if self.preload_ocr:
       rospy.loginfo("预加载 RapidOCR ...")
       _get_ocr()
       rospy.loginfo("RapidOCR 就绪")
   ```
   同时文件头参数说明补一行 `~preload_ocr`（默认 true，可 `preload_ocr:=false` 关闭）。
3. **同步**：`docker cp` 覆盖容器内 `src` 脚本（原文件已备份 `yolo_detector.py.bak_preload`）；`devel` 的 relay wrapper 直接 exec 源码，**改 src 无需重编译**。本地 `aic107` 同步相同改动。

## 结果与结论
- 语法校验通过（用容器 venv `/root/ylovenv/bin/python -m py_compile` 验证），行尾无 CR 污染。
- 改动已同步到容器与本地 `aic107` 两侧，默认行为即为预加载，无需改 launch。
- 生效方式：重启 `yolo_detector` 节点，启动日志应依次出现「加载阶段一权重 → 预加载 RapidOCR ... → RapidOCR 就绪 → YOLO 检测节点就绪」，之后巡逻中首次碰到车牌即可即时出字。
- 验证要点：同一进程内连续两次识别车牌，第一次与第二次均即时（对比修复前第一次卡 5-6 秒），即确认冷启动已提前。
