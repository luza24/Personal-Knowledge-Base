# AIC26 小车检查点语音播报与 Windows 本机转发

> 整理日期：2026年10月23日 20:57
> 项目：ROS仿真车 ｜ 状态：部分解决 ｜ 标签：`功能开发` `ros` `真车` `python环境` `git`

## 背景 / 目标

巡检任务到达检查点并触发视觉检测后，希望把识别结果用中文语音播报出来。最初方案是车端自己用 Kokoro TTS 合成并通过蓝牙音箱播放；后来确认当前阶段不接小车蓝牙，改为**小车只发布 `/speech`，由 Windows 电脑通过 SSH 接收并播放**。

目标：

- 识别结果文案统一收敛到 `mission_common.py`，`mission_controller` / `demo_cycle` 复用；
- 没有识别结果时静默，不播旧数据；
- 新增独立语音节点，尽量不侵入原有导航/感知代码；
- 把修改同步到实车，但不影响实车 `main` 和他人未提交改动。

## 报错记录

- **Kokoro 与 ROS Python 版本冲突**：Kokoro 需要 Python 3.10–3.12，ROS Noetic 是 3.8。不能直接 import，改为独立 venv + 子进程 worker。
- **git worktree 的 `src/CMakeLists.txt` 变成普通文本**：仓库配置 `core.symlinks=false`，新 worktree 把软链接检出成包含目标路径的文本文件，`catkin_make` 报
  `CMake Error at CMakeLists.txt:1: Parse error ... /opt/ros/noetic/share/catkin/cmake/toplevel.cmake`。
  修复：在新 worktree 内执行
  `rm src/CMakeLists.txt && ln -s /opt/ros/noetic/share/catkin/cmake/toplevel.cmake src/CMakeLists.txt`。
- **torch 官方源下载过慢**：`download.pytorch.org` 约 22MB/5 分钟；改用清华 PyPI 镜像
  `https://pypi.tuna.tsinghua.edu.cn/simple` 后很快完成。
- **非 UTF-8 locale 读 YAML 失败**：`real_tasks.yaml` 加入中文后，`open()` 默认编码可能不是 UTF-8；决策节点所有 YAML 读取和结果 JSON 写入统一加 `encoding='utf-8'`。
- **Windows 播放打断不可靠**：`winsound` 的 `SND_PURGE` 在现代 Windows 上行为不可靠；改用 `sounddevice`，新消息到来时 `sd.stop()` 并递增 generation。
- **rospy 日志混入 relay stdout**：车端 relay 用固定前缀 `AIC26_SPEECH ` + ASCII JSON 输出，PC 端只解析带前缀的行，其他 rospy 日志忽略。
- **`rostopic pub -1` 会保持约 3 秒**：正常现象，不是卡死。

## 修改方案

### 1. 车端检查点文案

`mission_common.format_result_message()` 根据检测 payload 生成中文：

- people：`本区域共检测到 N 人，其中 M 人为非社区人员。` / `...未发现非社区人员。`
- car：`检测到车辆，车牌号为 XXX。` / `检测到车辆，但未能识别车牌。`
- payload 为空或没有 `total`：返回空字符串，调用方不播。
- 车牌先去掉 `·`、空格等分隔符，避免 TTS 停顿。

`RobotDriver` 仅在传入 `speech_topic` 时创建 `SpeechAnnouncer`，其他节点（`capture_cycle`、`waypoint_follower`）行为不变。

#### 视觉结果 → /speech 的完整数据流

`/speech` 不是由视觉节点直接发布的，中间经过任务控制器组装：

1. `people_detector.py` / `car_detector.py` 收到 `/perception/detect` 后激活，向 `/perception/result` 发布 JSON（people 带 `total/intruder`，car 带 `total/plate`）。
2. `mission_controller.on_result()`（`mission_controller.py:127`）解析 JSON，按 `payload["target"]` 存入 `self.results`。
3. 到达 `inspect` 任务时（`mission_controller.py:217`）：
   - `self.results.pop(target, None)` 清掉上一站旧结果；
   - `trigger_detect(target)`（`:164`）向 `/perception/detect` 发目标，并等待 `detect_wait`（默认 1s）；
   - `speak(format_result_message(target, result, language))` 把中文发到 `/speech`。
4. `speech_bridge.py` 只订阅 `/speech`，不关心文本是人工 `rostopic pub` 还是视觉结果；视觉→文本的组装全部在车端完成。
5. 任务配置在 `real_tasks.yaml` 的 `inspect` 任务里用 `target: people/car` 指定检测目标，可加 `announce: false` 只检测不播。

### 2. 车端独立播报节点

```text
mission_controller --/speech--> speech_broadcaster (py3.8 ROS)
                                     │ stdin/stdout JSONL
                                     ▼
                              kokoro_worker (py3.10+ venv)
                                     │ paplay --device=<bluez sink>
                                     ▼
                               蓝牙音箱（当前阶段不用）
```

`kokoro_worker.py` 支持 `--check` 自检、逐段播放、取消事件；`speech_broadcaster.py` 负责启动/监控 worker、ready 前只保留最新一条、崩溃重启。

### 4. Windows 本机远程播报

本机没有 ROS，因此不装 ROS：

1. 本机 `speech_bridge.py` 用 `scp` 把 `speech_relay.py` 放到车端 `/tmp`；
2. 通过 `ssh -T vehicle "source /opt/ros/noetic/setup.bash && python3 -u /tmp/aic26_speech_relay.py"` 启动 relay；
3. relay 每收到一条 `/speech` 输出一行 `AIC26_SPEECH {"type":"speech","text":"..."}`；
4. 本机解析后交给 Kokoro，`sounddevice` 播放到 Windows 默认输出；
5. 新消息递增 generation 并 `sd.stop()`，实现打断；SSH 断开后自动重连。

一键启动：

```bat
"C:\Users\luza\miniconda3\envs\kokoro\python.exe" ^
  C:\Users\luza\Desktop\aic26_speech_pc\speech_bridge.py --ssh-host vehicle
```

也可以双击 `run_bridge.cmd`。

#### PC 桥接实现原理

```text
run_bridge.cmd
  └─ conda python 3.11 speech_bridge.py --ssh-host vehicle
       ├─ KokoroPlayer 线程：只加载一次 KPipeline(lang_code='z')
       ├─ scp speech_relay.py → vehicle:/tmp
       └─ ssh -T vehicle "source ROS; python3 -u relay.py"
                                  │
                                  ├─ rospy.Subscriber('/speech', String)
                                  └─ stdout: AIC26_SPEECH {json}
       ┌──────────────────────────┘
       ├─ read_stdout 线程：只解析 AIC26_SPEECH 前缀
       ├─ read_stderr 线程：普通日志
       └─ KokoroPlayer 线程：合成 → sounddevice → Windows 默认设备
```

- `speech_relay.py`：`emit()` 输出 ASCII JSON（`ensure_ascii=True`），`boot` 在 `rospy.init_node()` 前发出，用于区分 SSH 通了但 ROS master 没起；stdin 看门狗在 SSH 关闭时自动退出，避免孤儿节点。
- `speech_bridge.py`：`RelayClient.push_relay()` 每次用 `scp` 放 relay；`read_stdout()` 只处理带前缀的行，rospy 日志被忽略；`KokoroPlayer.submit()` 用 generation 计数器实现“新消息打断旧消息”，正在播放时立即 `sd.stop()`。
- 合成/播放：Kokoro 按句 chunk 产出 24kHz 音频，`sd.play(..., blocking=False)` 播放；设备不接受 24kHz 时自动重采样。
- 断线：SSH/relay 退出后按 2/4/8/30 秒退避重连，Kokoro 模型不重新加载；断线时调用 `player.cancel()`，避免重连后播放旧消息。
- 本地模式：`--once` / `--demo` 不连小车，用于先验证本机 TTS 与音频设备。
