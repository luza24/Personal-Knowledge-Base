# rviz 不显示 gazebo 小车与地图排查

> 整理日期：2026年9月27日 19:04

## 环境信息
- 操作系统：小车主板（ARM 板，疑似 Jetson），经 NoMachine 远程桌面操作
- ROS：Noetic，Gazebo 仿真 + rviz 可视化
- 部署方式：把本地 `catkin_ws` 工作区文件传到小车主板，在主板通过 NoMachine 编译后运行
- 工作空间：`~/catkin_ws`（`src/` 仅含 `aic26_*` + `gazebo_ros_model_color`，无硬件驱动包）

## 报错记录 / 现象
- 在小车主板上运行与 Docker 容器内效果不一致：
  1. **gazebo 能正常跑**，模拟界面的小车能正常显示、能开动；
  2. **rviz 加载不出地图**；
  3. **rviz 加载不出小车模型**；
  4. **键盘只能控制 gazebo 里的小车，操控不了实机**。

## 排查结论（根本原因，本次已定位）
1. **实机不能动**：`src/` 里从头到尾没有实机驱动节点。gazebo 里能开车靠的是 URDF 内联的
   `libgazebo_ros_skid_steer_drive.so` 插件，它只订阅 `/cmd_vel` 转仿真轮子，跟真实硬件无关。
   真实小车需要一个硬件驱动节点（订阅 `/cmd_vel` → 串口/CAN 发给电机驱动板），这个节点不存在。
   根目录 `diffbot_clone.bash` 是准备拉 `diffbot`/`rplidar_ros`/`raspicam_node` 的脚本，从未执行；
   `build/`/`devel/` 里的 `diffbot`、`rplidar_ros` 只是 x86_64 编译残留物，不是源码，ARM 上跑不了。
   即：Docker 里「能控制小车」其实一直是仿真车，不是实机。
2. **rviz 没地图**：`aic26_slam/maps/nav.yaml` 的 `image:` 写死 Docker 绝对路径
   `/root/catkin_ws/src/aic26_slam/maps/nav.pgm`，小车主板上无此路径，`map_server` 找不到 pgm。
3. **rviz 没小车模型**：rviz 是裸启动（`<node pkg="rviz" type="rviz"/>`），无 `.rviz` 配置，
   整个工作空间也没有任何 `.rviz` 文件，所以打开是空界面、什么都没 Add；且未接上
   `robot_description` 参数与 TF。URDF 链路为 `base_footprint→base_link→support→laser`（全 fixed），
   由 `robot_state_publisher` 发布（`gazebo_test.launch` 已起 RSP）。

## 涉及文件（本次改动）
- `src/aic26_slam/config/gmapping.rviz`（**新建**）：预设 Grid / Map(`/map`) / RobotModel(`robot_description`) /
  LaserScan(`/scan`) / TF 五个显示项，`Fixed Frame = map`。
- `src/aic26_slam/launch/gmapping.launch`：rviz 改为 `args="-d $(find aic26_slam)/config/gmapping.rviz"`；
  删掉硬编码静态 TF（`base_footprint→laser 0.265`，避免与 RSP 发布的 TF 冲突、`laser` 出现双父坐标系）。
- `src/aic26_slam/maps/nav.yaml`：`image:` 改为相对路径 `nav.pgm`（map_server 相对 yaml 目录解析，跨机器可移植）。

## 修改方案 / 关键改动
```yaml
# nav.yaml
image: nav.pgm
```
```xml
<!-- gmapping.launch 中 rviz 节点 -->
<node pkg="rviz" type="rviz" name="rviz" output="screen"
      args="-d $(find aic26_slam)/config/gmapping.rviz"/>
```

## 结果与结论
- rviz 地图/小车模型问题已给出修复（新建 rviz 配置 + launch 加载 + 改相对路径），待用户在小车主板验证。
- 实机控制问题**尚未解决**：需在小车主板单独搭一套硬件驱动工作空间（`diffbot`/`arbotix`/自研底盘
  驱动 + `rplidar_ros` + `raspicam_node`），用板上原生工具链编译，订阅 `/cmd_vel` 驱动电机、发布真实 `/odom`、`/scan`。

## 早期排查的其它候选原因（尚未排除）

> 2026-09-23 首轮排查时列出，9-27 收敛根因时未逐一验证，保留备查：

- **仿真时间不同步**：Gazebo 走仿真时间、rviz 默认真实时间，需
  `rosparam set /use_sim_time true` 后再启动 rviz。
- **话题名 / 类型不匹配**：`/scan` vs `/laser/scan`，`LaserScan` vs `PointCloud2`。
- **NoMachine OpenGL 渲染问题**：rviz / Gazebo 起不来或黑屏，可用
  `export LIBGL_ALWAYS_SOFTWARE=1` 验证。
