# 车端 WIT IMU 提升到 115200 baud / 100 Hz 的配置适配

> 整理日期：2026年11月06日 15:27
> 项目：ROS仿真车 ｜ 状态：已解决 ｜ 标签：`参数调优` `ros` `真车` `git`

## 背景 / 目标

车端 WIT IMU 的频率和波特率被提高后，检查 `aic26_ws_112` 的驱动配置是否还能工作、是否需要改代码。担心点是：驱动按固定波特率打开串口，若主机仍按 9600 打开，会完全收不到有效帧。

## 环境信息

- 实车：`192.168.1.15` / `mowen`，Ubuntu + ROS Noetic，Python 3.8
- 工作区：`/home/mowen/aic26_ws_112`（`speed-tuning`）
- IMU：WIT 标准协议，`/dev/imu -> ttyUSB0`
- 其他串口：`/dev/carserial -> ttyUSB1`、`/dev/lslidar -> ttyACM0`

## 排查结果

用 `pyserial` 直接探测 `/dev/imu`（3 秒）：

| 波特率 | 结果 |
|---|---|
| **115200** | `55 51/52/53/54` 四类帧各 **100.0 Hz**，3 秒 0 校验错，约 4404 B/s |
| 9600 | 只有乱码，0 个有效帧 |

而 112 的 `config/imu.yaml` 和 `launch/imu.launch` 仍写死 **9600**，`imu_node.py` 默认值也是 9600。按此启动时 IMU 节点会打不开有效帧，`/imu/data` 为 0 Hz，底盘 yaw 融合与 `hardware_status` 都会退化。

## 影响范围分析（为什么只改配置）

- `chassis_node` 只取最新陀螺样本；零偏更新发生在 20 Hz 底盘反馈回调里（`imu_gyro_bias_alpha` 的时间常数不随 IMU 频率变化），100 Hz 只是让样本更新鲜。
- `hardware_status` 超时 2.0 s、`chassis.yaml` 的 `imu_timeout` 0.2 s、各订阅 `queue_size` 都不受影响。
- `imu_node.py` 的 `read(64)` + 缓冲解析在 4400 B/s 下余量充足。
- 结论：**驱动逻辑不用改，只需把主机旁路配置与模块对齐。**

## 涉及文件

- `src/aic26_cobot/config/imu.yaml`：`baud: 9600 → 115200`，注释改为 2026-11-06 实测 100 Hz + 复位后退回 9600 的提醒
- `src/aic26_cobot/launch/imu.launch`：`<arg name="baud" default="115200"/>`（launch 值会覆盖 yaml，两处必须一致）
- `src/aic26_cobot/scripts/imu_node.py`：`get_param('~baud', 115200)` 作为独立运行兜底
- `src/aic26_cobot/README.md`、`HANDOVER.md`：设备表 / 当前配置 / 问题表第 16 条同步
- 未改：`aic26_ws` 与 `aic26_ws_speech` 仍为 9600；切换工作区时需再同步

## 修改方案

### 1. 三处默认值统一到 115200

```yaml
# config/imu.yaml
baud: 115200
```

```xml
<!-- launch/imu.launch -->
<arg name="baud" default="115200"/>
```

```python
# scripts/imu_node.py
self.baud = int(rospy.get_param('~baud', 115200))
```

### 2. 先备份到 GitHub，再改车端

按用户要求「先把当前版本传到 GitHub 再修改」：

1. 把 IMU 改动存成 patch；
2. 回退 5 个 IMU/文档文件；
3. 把 `speed-tuning` 上 18 个原有未提交改动提交为快照 `7044abf`（不含 `.bak_*`）；
4. `git bundle` 传到 Windows，在 `C:\Users\luza\Desktop\aic_real_car` 从本机用 `luza24` 身份推送到 `luza24/aic_real_car` 分支 **`aic26_ws_112_20261106`**；
5. 车端与桌面提交/tree 哈希一致（`7b96e24`），再重新应用 IMU patch。

车端身份 `Govis-Ink` 对 luza24 的仓库无写权限，必须从 Windows 侧推送。

## 验证

- 启动 `roscore` + `roslaunch aic26_cobot imu.launch`；
- `rostopic hz /imu/data` 稳定 **100.2 Hz**；
- `rostopic echo -n1 /imu/data`：静止时 `angular_velocity ≈ 0`，`linear_acceleration.z ≈ 9.87 m/s²`，四元数有限；
- 测试用 ROS 进程已全部清理。

## 结果与结论

- 已解决：IMU 在 115200 / 100 Hz 下工作正常，车端配置与模块一致，改动通过端到端验证。
- 残余风险：WIT 模块寄存器被复位后会退回出厂 **9600 / 10 Hz**（历史上发生过一次）。此时 `/imu/data` 为 0 Hz，应先用 `stty`/探测脚本确认模块实际波特率，**不要盲目把配置改回 9600**。
- 车端改动与 IMU 文档改动保持未提交，等用户统一提交。
