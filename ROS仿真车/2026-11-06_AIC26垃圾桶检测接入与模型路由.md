# AIC26 垃圾桶检测接入与视觉模型路由

> 整理日期：2026年11月06日 20:30
> 项目：ROS仿真车 ｜ 状态：部分解决 ｜ 标签：`功能开发` `ros` `perception` `yolo` `真车`

## 背景 / 目标

在 `aic26_ws_112` 的 `inspect` 任务里新增垃圾桶视觉类别（target 定为 `rubbish`），同时把 person / traffic_light / car / rubbish 的模型选择集中到 bringup 入口，并把 car 异常无结果时的等待时间从 12 s 调到 5 s。

## 环境信息

- 实车：`192.168.1.15` / `mowen`，Ubuntu + ROS Noetic，Python 3.8
- 工作区：`/home/mowen/aic26_ws_112`（`speed-tuning`）
- 推理：OpenVINO CPU、2 threads；相机 `/dev/video0`（话题 `/camera/image_raw`）
- v2 视觉协议：`/perception/detect` 请求、`/perception/result` 结果、每个 target 自己的 `/perception/<target>/protocol`

## 报错记录

### 1. 垃圾桶 target 命名不能带空格

用户最初把 target 叫 `rubbish bin`。日志/JSON 里可以用空格，但 ROS topic 名不能含空格，最终内部 target 用 **`rubbish`**：

- `/perception/rubbish/protocol`
- `/perception/rubbish/image`

任务 YAML 里的 `target` 必须写 `rubbish`，不能写 `rubbish bin`。

### 2. 首次 ROS 冒烟出现 `Infer Request is busy`

fp32 模型单帧推理可能超过相机周期，第二帧回调重入 OpenVINO 时报：

```text
RuntimeError: Infer Request is busy
```

处理：在 `rubbish_detector.py` 里加非阻塞推理锁，busy 时直接丢这一帧：

```python
if not self.infer_lock.acquire(False):
    return
try:
    dets = self.infer(frame)
finally:
    self.infer_lock.release()
```

加锁后冒烟测试 0 个 Traceback / ERROR。

## 修改方案

### 1. 模型与类别

`rabbish.onnx` 用 onnxruntime 核对元数据：

- 输入 `[1,3,640,640]`，输出 `[1,12,8400]`（4 + 8 类）
- 类别顺序：`harmful_open, harmful_close, kitchen_open, kitchen_close, other_open, other_close, recyclable_open, recyclable_close`
- 安装为 `models/rubbish.onnx`，`conf` 0.25、`nms` 0.45

### 2. 检测器 `rubbish_detector.py`

沿用 people 的 v2 结构：

- 首帧开启观察窗口，`observe_time=0.8 s`、`min_frames=2`；
- 逐帧按类别去重，窗口结束取众数，只发一次 `complete=true`；
- 结果字段：`total`、`open`、`close`、`bins`、`open_bins`、`close_bins`、`boxes`、`frames`、`observe_s`、`selected_frame`；
- 只在请求期间订阅 `/camera/image_raw`；收到其它 target 请求时关闭自己；
- protocol 初始 + 1 s 周期重发，避免启动时序漏 latch；
- 加推理锁（见上）。

### 3. mission_controller 最小改动

1. `protocol_topics` 增加：
   ```python
   'rubbish': rospy.get_param('~rubbish_protocol_topic',
                              '/perception/rubbish/protocol'),
   ```
2. inspect 超时与 people 共用：
   ```python
   timeout = (self.people_detect_timeout
              if target in ("people", "rubbish")
              else self.car_detect_timeout)
   ```
3. `run()` 的 required 白名单加入 `"rubbish"`。

播报使用任务 YAML 里的固定 `message`，未改 `format_result_message`。

### 4. 模型选择集中到 bringup

`aic26_bringup/launch/mission.launch` 新增四个可命令行覆盖的 arg：

```xml
<arg name="people_model"        default=".../models/person.onnx"/>
<arg name="traffic_light_model" default=".../models/traffic_light.onnx"/>
<arg name="car_model"           default=".../models/car_int8.onnx"/>
<arg name="rubbish_model"       default=".../models/rubbish.onnx"/>
```

并分别透传给四个 perception include 的 `model_path`。旧的 `people_int8.onnx` / `traffic_int8.onnx` 保留作回滚，已无代码引用。

### 5. car 异常等待时间

`car_detect_timeout` 从 **12.0 s → 5.0 s**：

- `aic26_bringup/launch/mission.launch`
- `aic26_decision/launch/mission.launch`
- `mission_controller.py` 的 `rospy.get_param('~car_detect_timeout', 5.0)` 兜底

注意：`car_request_timeout`（OCR 超时）仍是 10.0 s；有车但 OCR 超过 5 s 时，mission 会先放弃。

## 验证

- 模型元数据：8 类顺序与 README 一致，输出 `[1,12,8400]`；
- 离线推理：用旧的人员样本图能加载并解码（出现一次 `kitchen_close` 误检，说明空场景可能误报）；
- ROS 节点冒烟：protocol v2、`/perception/result` 返回 `target=rubbish`、`request_id` 匹配、`complete=true`，无 Traceback/ERROR；
- `roslaunch --dump-params aic26_bringup mission.launch backend:=real` 确认四个模型路径正确，命令行覆盖也生效；
- **未验证**：真实垃圾桶图的召回率、实车红/黄/灭灯无关；rubbish 任务尚未在实车跑通。
