## 报错记录（7 个，逐个解决）

### 1. docker cp 复制 symlink 失败
`A required privilege is not held by the client`（顶层 CMakeLists.txt 是软链接）。
→ 改用 tar 流跳过 symlink，再在宿主机补一个内容相同的普通文件。

### 2. 工作区路径固化 `oi~` 导致 rospack 找不到包
解压时目录名打成 `~/oi~/catkin_ws`，`catkin_make` 后 build/devel 固化了旧路径。`mv` 到 `~/catkin_ws` 后 `rospack find` 报 not found、重新 `catkin_make` 报 `CMakeCache.txt directory is different`。
→ `rm -rf build devel` 后重新 `catkin_make`。

### 3. venv 里 `No module named 'ultralytics'` / `rospy` 缺 `rospkg`
ylovenv 是空壳，且 ROS 系统包（rospkg 等在 `/usr/lib/python3/dist-packages`）venv 找不到。
→ 补装依赖 + `pip install rospkg catkin_pkg`。

### 4. filelock 版本冲突（关键坑）
```
ImportError: cannot import name 'AsyncFileLock' from 'filelock' (/usr/lib/python3/dist-packages/filelock.py)
```
**根因**：之前为解决 rospkg 找不到，往 `~/.bashrc` 加了
`export PYTHONPATH=...:/usr/lib/python3/dist-packages`，且 `.bashrc` 里 source 了 zxt/bit_ws 的 setup.bash，
这些把系统旧版 filelock 插到 sys.path 最前，遮蔽了 venv 新版 filelock。
**解决**：删 `.bashrc` 里的 PYTHONPATH，改写在 venv 的 `ros.pth`（追加到 sys.path 末尾，venv 包优先）；
启动视觉节点前 `unset PYTHONPATH`。

### 5. 相机 `Permission denied`
`/dev/video0` 属组 video（`crw-rw---- root video`），但当前会话进程没 video 组。
→ `usermod -aG video mowen` + **注销重新登录**（`newgrp video` 可临时生效）。

### 6. `rosrun usb_cam` 报 `Failed to contact master`
单独 `rosrun` 不会起 master，且注销后原 roslaunch 拉起的 master 已死。
→ 先 `roslaunch`（自动起 master）或 `roscore`，再起相机。

### 7. 话题名不一致（最后一步）
代码订阅 `/camera/image_raw`（仿真名），真车 usb_cam 发布 `/usb_cam/image_raw`。
`/camera/image_raw` 是僵尸话题（只有订阅者无发布者），永远无数据。
→ 在 `perception.launch` 的 yolo_detector 节点加 `<remap from="/camera/image_raw" to="/usb_cam/image_raw" />`。

## 补充：底盘/雷达/IMU 驱动 + 传感器搬进 catkin_ws（2026-10-01）

### 传感器硬件识别（udev 规则对不上，靠 ID 识别）
| 传感器 | 实际串口 | USB ID | 识别依据 |
|---|---|---|---|
| 激光雷达（镭神 N10_P） | /dev/ttyACM0 | 1a86:55d4 | lslidar 链接已生效 |
| IMU（维特 WIT） | /dev/ttyUSB0 | 1a86:7523 | 读数据 0x55 帧头 |
| 底盘（麦克纳姆轮） | /dev/ttyUSB1 | 1a86:7523 | 读数据 0xAA 0xBB 帧头 |

- 原 udev 规则（carserial.rules 找 ttyUSB1、imu.rules 找 usb-0:6.1）与实际 USB 位置（6.3/6.4/6.1）对不上，`/dev/carserial`、`/dev/imu` 链接均不存在。
- **临时解决**：`sudo ln -sf /dev/ttyUSB1 /dev/carserial`、`sudo ln -sf /dev/ttyUSB0 /dev/imu`（**重启失效**，需固化进 udev 规则）。
- 密码 `123456`，SSH 非交互下用 `echo "123456" | sudo -S`。

### 底盘驱动链路
```
/cmd_vel → newt.py（订阅cmd_vel，转串口协议发指令，读/dev/carserial 115200）
底盘编码器 → pubv.py（读/dev/carserial，发/vel_raw）
/vel_raw → base_node（C++，积分成 /odom_raw）
/odom_raw + /wit/imu → EKF(robot_localization) → /odom + odom→base_footprint TF
```
- TF 树完整：`map → odom → base_footprint → base_link → laser_link`
- 话题名：`/odom`（EKF 输出）和 `/cmd_vel`（newt 订阅）正好对得上 patrol 脚本，无需 remap。

### 报错 8：传感器驱动搬进 catkin_ws 后 catkin_make 失败
```
fatal error: lslidar_msgs/LslidarPacket.h: 没有那个文件或目录
```
**根因**：`lslidar_driver` 的 CMakeLists 里 `lslidar_input` 库缺 `add_dependencies(...${catkin_EXPORTED_TARGETS}...)`，导致 catkin_make 顺序编译时消息头文件未先生成（zxt 用 catkin build 并行编译所以没暴露）。
**解决**：在 `add_library(lslidar_input ...)` 后补 `add_dependencies(lslidar_input ${${PROJECT_NAME}_EXPORTED_TARGETS} ${catkin_EXPORTED_TARGETS})`。

### 报错 9：newt.py 启动报错
```
rospkg.common.ResourceNotFound: mbot_bringup
```
**根因**：`newt.py`/`newt2.py`/`pubv.py`/`pubv2.py` 里有废代码 `import roslib; roslib.load_manifest('mbot_bringup')`，而 catkin_ws 里没有 mbot_bringup 包。
**解决**：注释掉这行（旧 ROS 写法，对运行无用）。

## 补充：udev 串口规则修复 + patrol 脚本坐标对齐（2026-10-02）

### 报错 10：重启后建图无数据（IMU/底盘串口交叉）
- **现象**：重启主板后 `roslaunch car_bringup gmapping.launch`，雷达 `/scan` 正常 10Hz，但 IMU、底盘、里程计全无数据，gmapping 报 `MessageFilter [target=odom] Dropped 100%`（等不到 `odom→base_footprint` TF，建图不启动）。
- **根因**（用数据帧头硬验证定位）：**IMU 和底盘的 USB 线插反了**（物理端口与旧记录对调）。
  - 底盘（麦克纳姆轮）：实际 `ttyUSB0`（6.1），帧头 `0xAA 0xBB`，@115200
  - IMU（维特 WIT）：实际 `ttyUSB1`（6.3），帧头 `0x55`，@9600
  - 之前写的 udev 规则按旧端口把 `imu→6.1`、`carserial→6.3`，导致两个驱动节点交叉读串口，都解析不出对方帧头 → EKF 无输入 → `/odom` 空 → gmapping 全丢弃。
- **修复**：修正 `/etc/udev/rules.d/85-car-serial.rules`，对调符号链接（用 `ENV{ID_PATH}` 按物理端口区分，因 IMU/底盘都是 CH340、USB ID 相同 `1a86:7523` 无法用 ID 区分）。
  ```
  SUBSYSTEM=="tty", ENV{ID_PATH}=="pci-0000:00:14.0-usb-0:6.1:1.0", MODE:="0666", SYMLINK+="carserial"
  SUBSYSTEM=="tty", ENV{ID_PATH}=="pci-0000:00:14.0-usb-0:6.3:1.0", MODE:="0666", SYMLINK+="imu"
  ```
- **两个关键坑**：
  1. 规则文件名用 `10-` 会执行太早，`ENV{ID_PATH}` 还没被系统 60 号规则设置 → 匹配失败；必须用 `60` 之后（本方案 `85-`）。
  2. 修改规则后，之前已启动的进程攥着旧的（错误的）文件描述符，必须**杀掉重启**才能读到新符号链接。

### patrol_green_test.py 坐标对齐改造（真车复现仿真巡逻）
- **背景**：patrol 脚本逻辑已完整（原地转向 waypoint + 红绿灯检测 + 旋转/任务点），接口全对得上真车（订阅 `/odom`、发 `/cmd_vel`、调 `/yolo/detect`），唯一障碍是脚本坐标是「场地坐标」而真车 odom 是「相对启动点 + IMU 绝对航向」。
- **EKF 坐标本质**：`odom0_config` 位置三项全 false（只融合速度积分 → x/y 相对启动点），`imu0_config` 姿态三项全 true（yaw 来自 IMU 绝对航向）。故 odom 原点=启动点、yaw=IMU 绝对航向。
- **改动**（`patrol_green_test.py`）：
  1. 速度参数适配麦轮：`MAX_V` 0.4→0.25、`MAX_W` 1.5→1.0（脚本注释自己也写滑移底盘别超 1.0）。
  2. 加「坐标对齐刚体变换」：新增常量 `START_POS_X=1.70`、`START_POS_Y=1.68`、`START_YAW=3.152`（对齐仿真 spawn 点 (1.70,1.68)、车头朝 -x）；`odom_cb` 里启动时自动记录 `yaw0`，之后每帧 `theta=START_YAW-yaw0`，把 odom 旋转+平移映射回场地坐标。
- **前提**：每次启动车都停在同一个场地位置（1.70,1.68，场地一角）、同一朝向（车头朝 -x），否则坐标乱。原脚本备份 `patrol_green_test.py.bak`。
