## 报错记录

### 1. 实车启动 traffic protocol 缺失

第一次实车启动时 mission 拒绝开始任务：

```text
detector protocol v2 missing for: traffic_light
mission not started: detector protocol mismatch
```

traffic detector 的 latched protocol 在 mission 订阅前发布；当前 rospy/启动时序下没有补发，车没有行驶。

修复：给 `traffic_light_detector.py` 增加 1 秒周期重发 protocol：

```python
self.protocol_timer = rospy.Timer(
    rospy.Duration(1.0), self._republish_protocol)
```

备份：`traffic_light_detector.py.bak_20261105_protocol_timer`。

### 2. 实车旧 ROS 残留

抓图轮曾遇到多个残留 `gzserver/gzclient/rosmaster/roslaunch`，load average 8+，detector 卡在模型加载。清理脚本必须用独立文件执行，避免在同一个 shell 里 `pkill -f` 匹配到自身命令行导致 SSH 断开。

## 修改方案

### 1. v2 请求/结果协议

命令：

```json
{"schema":2,"target":"people","request_id":"<run_uuid>:<seq>"}
{"schema":2,"target":"stop","request_id":"<run_uuid>:<seq>"}
```

结果增加：

```json
"request_id", "session", "complete", "schema"
```

- 三个 detector 启动发布 protocol topic，mission 只检查任务实际用到的 target；
- stop 只在 request_id 匹配时生效；v2 active 时无 ID 的 legacy stop 被拒绝；
- mission 只接受当前请求且 `complete=true` 的结果。

### 2. people 计数

- 观察窗口从第一帧开始：
  - 仿真 `observe_time=3.0s`、timeout=10s；
  - 实车 `observe_time=0.8s`、timeout=4s。
- 最终人数取观察窗口内各帧人数的**众数**：
  - 每帧按类别去重；
  - 众数并列取较大值；
  - 同一人数取最后一帧；
  - `boxes/community/intruder` 都来自选中帧；
  - 不再把不同帧的人相加。
- 结果示例：

```json
"frame_counts": [0, 0, 0, 0],
"selected_frame": 4,
"total": 0
```

### 3. car OCR

- EasyOCR 后台预加载，ready topic 只做诊断，不阻止巡逻；
- OCR 异步执行，最终结果只封存一次；
- `ocr_status` 支持 `ok/empty/failed/timeout/no_car`；
- 最终结果之后迟到的 OCR 丢弃；
- car 站缺车时约 1s 提前完成，不再等满 12s。

### 4. traffic light

- 保留 latched `TrafficLightState`；
- 新增按 request_id 匹配的 JSON event；
- 仿真 truth 优先，实车使用 vision + `light_fallback=traffic_light`；
- 1 秒 protocol 重发解决实车启动漏 latch。

## 结果与结论

- v2 检测协议、people 观察窗口/单帧众数、car 预加载/最终结果、traffic 事件、mission dwell 并行和电脑端语音链路已在仿真和实车跑通；
- 实车导航 18 任务完整结束，PC 端 9 条播报全部收到；
- **实车视觉质量仍然不足**：
  - people 多数站点为 0；
  - car 把桌面设备误检为车，OCR 多为 empty/timeout；
  - traffic 未在 10s 内给出有效绿灯。
- 这是相机安装角度、站点构图、模型训练数据和车牌 ROI 问题，不是请求协议或 mission 流程问题。下一步优先检查实车相机视角与站点构图，再考虑模型微调。
