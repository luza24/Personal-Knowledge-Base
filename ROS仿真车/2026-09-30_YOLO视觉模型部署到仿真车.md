# YOLO 视觉模型部署到仿真车

> 整理日期：2026年9月30日 15:02

## 环境信息
- 操作系统：Windows 11 + WSL2 / 虚拟机（Ubuntu 20.04，ROS Noetic）
- 项目：aic26，导航脚本在 `aic26_navigation` 包，视觉节点落在 `aic26_perception` 包
- 底盘：滑移转向底盘（差速），`/odom`（nav_msgs/Odometry）、`/cmd_vel`（geometry_msgs/Twist）
- 相机：Gazebo 插件 `libgazebo_ros_camera.so`，话题 `/camera/image_raw`（1280×720，R8G8B8）
- 视觉：ultralytics YOLO，训练权重 `aicyolo/runs/detect/train/weights/best.pt`
- 类别（来自 `aicyolo/data.yaml`）：`0 person` / `1 bad_person` / `2 car` / `3 number_plate` / `4 traffic_lights`
- **（9月30日补充）运行容器**：`ros_noetic_gazebo`（镜像 `osrf/ros:noetic-desktop-full`），系统 Python 3.8.10、pip 20.0.2、numpy 1.17.4
- **（9月30日补充）独立 venv** `/root/ylovenv`：numpy 1.24.4、opencv-python 5.0.0、torch 2.4.1、torchvision 0.19.1、ultralytics 8.4.166

## 报错记录 / 问题
1. **红绿灯类别无训练数据**：`best.pt` 训练时 `traffic_lights`（类别 4）标注数为 **0**（person=247、bad_person=43、car=34、number_plate=43），无法靠 YOLO 识别红/黄/绿灯色。→ 用户决定「红绿灯先不管」，只识别人物/车牌/车辆/可疑人员。
2. **Edit 工具报错** `File has been modified since read, either by the user or by a linter`：`patrol_green_test.py` 在我读后被外部改动（SPIN_POINTS 第三点从 `(-0.9,1.1)` 改成 `(-0.9,0.6)` 等）。→ 需先 Read 重读再 Edit。
3. **（9月30日补充）容器 `pip install ultralytics` 失败**：根因不是下载，而是**依赖冲突**——ROS noetic 自带 numpy 1.17.4，ultralytics 8.x 要求 `numpy>=1.23`；若强行升级 numpy 会破坏 `cv_bridge`（其按 numpy 1.17 ABI 编译）。桌面 ultralytics 源码安装同样绕不开 torch/numpy 依赖。→ 用独立 venv 隔离。
4. **（9月30日补充）`python3 -m venv` 失败**：报 `ensurepip is not available` → 需 `apt install python3.8-venv`。
5. **（9月30日补充）Git Bash 路径转换坑**：命令里写 `/root/ylovenv/bin/pip` 被 MSYS 转成 `D:\root\ylovenv\bin\pip` 报 `command not found` → 改用 `$HOME/ylovenv/bin/pip` 规避。

## 修改方案

### 1. 独立 YOLO 检测节点（aic26_perception）
- 订阅 `/camera/image_raw`（`queue_size=1, buff_size=2**24`），用 `cv_bridge` 转 bgr8 并缓存最新一帧。
- 提供 `/yolo/detect` 服务（`std_srvs/Trigger`）：收到请求 → 对最新一帧跑一次 `model(frame, verbose=False)` → 统计各类别数量 → 返回 JSON 字符串（`类别→数量`）。
- 同时发布到 `/yolo/detections`（std_msgs/String）。
- 两把锁：`self.lock` 保护帧、`self.infer_lock` 串行化推理（避免并发跑模型）。
- 类别名从 `self.model.names` 动态读取，不硬编码。

### 2. 巡逻脚本接入（patrol_green_test.py）
- 删除占位的 `detect_traffic_light()`，新增 `detect_objects()`：调 `/yolo/detect` 服务，`json.loads` 解析后 `rospy.loginfo` 打印「人物/车牌/车辆/可疑人员」数量。
- 配置区 `LIGHT_ZONES` → `DETECT_ZONES`（沿用原坐标 `(0.9,1.7)`、`(0.0,-0.1)`），`DETECT_RADIUS=0.2`、`DETECT_WAIT=5.0`。
- 状态变量：`detecting` / `detect_start_time` / `active_zone_idx` / `yolo_proxy`（模块级全局）。
- 主循环：进检测点 → `detecting=True` → 先 `pub.publish(Twist())` 停稳 → `detect_objects()`；停满 `DETECT_WAIT` 后 `detecting=False` 并切下一个检测点；停车期间 `cmd` 全零。
- 入口 `__main__` 里 `rospy.wait_for_service('/yolo/detect', timeout=30)` 后 `rospy.ServiceProxy(...)` 初始化 `yolo_proxy`（脚本为顶层代码结构，全局读写安全）。

### 3. （9月30日补充）升级为两阶段红绿灯检测
- 换模型：新增阶段二 `tl_state_det.pt`（red/green/yellow，来自桌面 `aic26小车视觉模块/tl_state_det.pt` = `runs/detect/train-2/weights/best.pt`）。
- `yolo_detector.py` 改为两阶段：stage1 跑 5 类；检出 `traffic_lights`（cls=4）后 crop 该区域交给 stage2 判红/绿/黄。
- 返回 JSON 保持扁平计数兼容：`person/bad_person/car/number_plate` + 新增 `traffic_lights`、`red/green/yellow`。

### 4. （9月30日补充）独立 venv 运行（解决 ultralytics 安装失败）
- 建 venv 并装依赖：
  ```bash
  apt-get install -y python3.8-venv
  python3 -m venv $HOME/ylovenv
  $HOME/ylovenv/bin/pip install --upgrade pip -i https://pypi.tuna.tsinghua.edu.cn/simple/
  $HOME/ylovenv/bin/pip install numpy opencv-python torch torchvision ultralytics -i https://pypi.tuna.tsinghua.edu.cn/simple/
  printf "/opt/ros/noetic/lib/python3/dist-packages\n/usr/lib/python3/dist-packages\n" > $HOME/ylovenv/lib/python3.8/site-packages/ros.pth
  ```
- `ros.pth` 把 ROS 包（rospy/genpy/genmsg/sensor_msgs…）与系统包（rospkg/catkin_pkg/netifaces/yaml…）都接入 venv。
- 去 cv_bridge：`yolo_detector.py` 改用 `numpy.frombuffer(msg.data)` 解码 `sensor_msgs/Image`（bgr8/rgb8/mono8/bgra8/压缩图兜底），绕开 numpy ABI 冲突。
- launch 用 `launch-prefix="$(arg python)"` 指定 `/root/ylovenv/bin/python` 跑节点，避免 catkin 安装时重写 shebang 的问题。

### 5. 运行步骤（9月30日更新，改用 venv）
```bash
cd ~/catkin_ws && catkin_make && source devel/setup.bash
roslaunch aic26_gazebo aic26-1.launch        # 仿真
roslaunch aic26_perception yolo_detector.launch  # YOLO 节点（venv 跑）
rosrun aic26_navigation patrol_green_test.py     # 巡逻+检测
```

## 结果与结论
- 两个脚本均通过 `python -m py_compile` 语法检查；旧变量（`stop_start_time`/`LIGHT_ZONES`/`detect_traffic_light`）已无残留引用。
- 架构 = 独立 YOLO 节点 + Trigger 服务，导航节点与视觉解耦，便于替换权重/类别。
- 未在 Gazebo 实测。注意点：YOLO 推理为阻塞调用（1280×720 CPU 上约数百 ms~1s），但触发时车已停车、无影响；进点先发零速再推理避免滑行。
- 红绿灯灯色暂不处理（`traffic_lights` 标注为 0）；后续若需可走两条路：① 补数据重训灯色类别；② 读 `traffic_light_controller` 已算好的相位（该 C++ 目前只订阅、未发布灯色话题）。
- **（9月30日补充）两阶段 + venv 已端到端验证通过**：venv 内 `import rospy/genpy/genmsg/sensor_msgs/std_msgs/std_srvs/ultralytics/torch/cv2` 全通；两个模型（best.pt + tl_state_det.pt）加载并前向推理 OK（stage1 5 类、stage2 red/green/yellow 类别名正确）；`roslaunch` 冒烟测试节点启动、加载模型、打印「服务 /yolo/detect 就绪」并正常 spin。
- **（9月30日补充）注意**：torch 装的是 cu121 版（约 1GB，含 CUDA 依赖），容器无 GPU 走 CPU 推理；如需瘦身可改 `--index-url https://download.pytorch.org/whl/cpu` 装 CPU-only。venv 在容器内，重建镜像/容器后需按第 4 节命令重装。

## 补充：视觉包三处升级（2026-10-01）

### 需求
1. 5 类检测模型从 `train` 轮换成更晚的 `train-3` 轮权重。
2. 红绿灯状态判定从「阶段二 YOLO 模型 tl_state_det.pt」改为**第三版的 HSV 色彩启发式**（省一个模型）。
3. 新增**车牌 OCR**（RapidOCR 读车牌文字）。

### 涉及文件（容器 /root/catkin_ws/src/aic26_perception）
- `weights/best.pt` —— 替换为 train-3（原文件备份 `best.pt.bak_train`）
- `scripts/yolo_detector.py` —— 去 stage2、加 `tl_state_hsv` + `read_plate`、JSON 加 `plates`
- `scripts/yolo_save_node.py` —— 同上改造
- `launch/*.launch`（3 个）—— 删除 `stage2_weights` 参数
- 备份：脚本/launch 各加 `.bak_stage2`

### 修改方案
1. **换权重**：`docker cp` 宿主机 `第三版/runs/detect/train-3/weights/best.pt` 进容器覆盖 `best.pt`（MD5 `0ef1e83b...`）。train-3 与旧 best.pt 同为 yolov8s 5 类、同 data.yaml，无需改检测代码。
2. **装 OCR 依赖**到 `/root/ylovenv`：`pip install onnxruntime rapidocr_onnxruntime`（onnxruntime 1.19.2、rapidocr_onnxruntime 1.4.4）。
3. **HSV 替换 stage2**：照搬第三版 `infer_two_stage.py` 的 `tl_state_hsv()`——红绿灯 crop 转 HSV，取「高饱和+高亮」发光灯头最纯像素的色相 H：`hue≤12 或 ≥168→red`、`≤55→yellow`、`≤110→green`，亮像素<30 或其余→unknown。删除 `self.stage2 = YOLO(...)` 加载。
4. **OCR**：新增 `_get_ocr()`（懒加载，兼容导入）+ `read_plate()`，对 cls=3（number_plate）crop 识别，清洗只留数字/字母/中文。
5. **返回契约**：`/yolo/detect` JSON 保持扁平计数（兼容 patrol），新增 `"plates": [...]` 字段存车牌文字；标注图不画中文（容器无中文字体）。

### 关键坑：rapidocr 接口差异
- 第三版针对**旧 `rapidocr`** 写的 `read_plate` 用 `.txts`/`.scores` 属性，但容器装的是 **`rapidocr_onnxruntime`**，返回 `(result, elapse)` 元组，`result` 为 `[[box, text, score], ...]` 或 None。
- 适配：`result = res[0] if isinstance(res, tuple) and len(res)==2 else res`，取 `max(result, key=lambda x: x[2])` 的 `x[1]` 为文字。

### 结果与结论
- 静态验证通过：`py_compile`、`catkin_make`、模型加载（5 类名正确）、HSV 纯色块四态（red/green/yellow/unknown）全对、OCR 真实车贴图能读出 `B8`/`苏A` 残片。
- **train-3 相比 train 几乎无提升**：两轮同为 yolov8s/100epoch/batch4，mAP50-95 都约 0.82（train 0.823 vs train-3 0.824），数据/超参未变只是重训。
- **OCR 在仿真车牌只能读到残片**：Gazebo 车辆是 `car_board` 照片贴图，无独立车牌模型，车牌是贴图一部分且很小，OCR 读不全——这是仿真数据限制，非代码问题。
- 启动方式不变：`roslaunch aic26_perception perception.launch`（内部已不再加载 tl_state_det.pt）。
