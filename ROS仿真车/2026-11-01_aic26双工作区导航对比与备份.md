## 背景 / 目标

两件事在一次对话里完成：

1. 把车端 `/home/mowen/aic26_ws_speech` 工作区（**含未提交改动**）传到备份仓库 `luza24/aic_real_car`；

结论先行：**两个工作区在 `5d9e976` 分叉。main 走的是实车定位鲁棒性路线，导航参数更新到今天（11-01 17:22–17:59，尚未提交）；speech 走的是语音播报 + 更多巡检点路线，导航参数停在 10-28。导航栈应以 main 为准，speech 的播报与任务表是其独有价值。**

## 报错记录 / 踩坑

- `tar: src/CMakeLists.txt: Cannot create symlink to '/opt/ros/noetic/share/catkin/cmake/toplevel.cmake'`：该文件是软链接，Windows 无法创建；GNU tar 失败前会先删掉本地已有文件，导致本地仓库出现 `D src/CMakeLists.txt`，需 `git checkout --` 恢复。**传输时必须用 `[ -L "$f" ] ||` 过滤软链接。**
- 本地 4 个 `.cmd` 误报 `M`：`core.autocrlf=true` + 仓库 `.gitattributes` 的 `eol=lf` 冲突所致，工作区文件 md5 与车端完全一致；对这 4 个文件 `git add` 后状态即干净。
- GNU tar 的 `--no-recursion` 放在 `-T -` 之后会警告且无效；文件清单本来就是文件级，直接省掉该参数。

```bash
# 车端 → 本机
ssh mowen@192.168.1.15 'cd /home/mowen/aic26_ws_speech && \
  git ls-files -co --exclude-standard -z | \
  while IFS= read -r -d "" f; do [ -L "$f" ] || printf "%s\0" "$f"; done | \

```

main=`7cb079e`、speech=`0e4dd2b`，再做树对树 diff。

## 关键判断

- **main 是更新的实车调参**：omni 模型、虚拟墙、定位自检、定位看门狗、真车八边形足迹、`world_real` 清洗地图、参数化 launch；11-01 还在继续调（速度包络上调、AMCL 粒子/更新收紧、inflation 与 TEB 权重回摆）。
- **speech 的导航栈是 10-28 的窄道调参**（对应 `docs/aic26_speech_nav_tuning_20261028.md`），没有真车足迹与定位看门狗；若直接上实车，足迹偏小、无定位丢失兜底、障碍层范围参数无效、地图用未清洗的 `world.yaml`。
- **两边互补**：main 缺中文播报/结果格式化/更多巡检点；speech 缺定位鲁棒性与真车几何。`mission_common.py` 两边各改了一大块（main 的 watchdog vs speech 的 SpeechAnnouncer），**必须手工合并，不能整文件覆盖**。
- main 的 `global_planner_params` 双重命名空间问题 speech 已修，反向合并时可一并带入。

## 结果与结论

- **备份完成**：新提交 `c7ee0b4`，远程 `luza24/aic_real_car` 的 `main` 已更新；本机仓库工作区干净，车端工作区未改动。
- **对比完成**：导航栈以 main 为底座，合入 speech 的播报与任务表是最合理的统一方向。
- **遗留 / 待验证**：
  1. main 今天 17:22–17:59 的导航改动（AMCL 粒子/更新、速度包络、costmap/planner）**尚未提交**，是否已在车上验证待确认；
  2. 两边 `mission_common` / 任务表尚未合并；
  3. speech 若在实车运行，需先修足迹、补看门狗、改 `obstacle_layer` 参数层级、换 `world_real` 地图。
