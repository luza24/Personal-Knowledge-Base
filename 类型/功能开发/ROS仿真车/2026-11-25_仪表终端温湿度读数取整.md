# 仪表终端报告行温度/湿度读数取整（aic26_ws_112 实车）

> 整理日期：2026年11月25日 07:21
> 项目：ROS仿真车 ｜ 类型：功能开发 ｜ 状态：已解决 ｜ 主题：`感知与视觉` ｜ 标签：`ros`、`真车`、`perception`

## 背景 / 目标

gauge（meter）航点停车后，`mission_controller` 会向终端打印固定三段式报告行：

```text
[REPORT] 温度表读数为26.5度。湿度表读数为54.5%。电表读数为235.1kWh
```

温度、湿度表盘读数带一位小数，不符合交付要求：**表盘数字四舍五入、不要小数位**。
电表读数是 LCD OCR 结果（`235.1kWh`），小数点有意义，保持原样。

根因在 `mission_common.py` 的 `_format_gauge_terminal_value()`：整数时输出 `%d`，
否则回退 `%.1f`。上游 `gauge_common.py` 按 `gauge.yaml` 的 `resolution: 1.0` 输出
`reported_text` 本是整数，但终端行用的是 payload 里 `round(value, 2)` 的原始 `values`，
所以会出现 26.5 这类值。

## 修改方案

### 取整规则

`round()` 在 Python 3 是银行家舍入（26.5→26），不符合「四舍五入」，改为半远离零：

```python
def _format_gauge_terminal_value(value):
    try:
        number = float(value)
    except (TypeError, ValueError):
        return '--'
    if number >= 0:
        return '%d' % int(math.floor(number + 0.5))
    return '%d' % int(math.ceil(number - 0.5))
```

- 温度量程含负值（-30…50 °C），负温按绝对值进位：-26.5 → -27；
- 缺失/非数值仍输出 `--`；
- `math` 文件头已导入，无需新增依赖。

### 测试

`test_gauge_terminal.py` 的 `NumberFormatTest` 拆成三例：

- 26.5 / 54.5 → `27` / `55`（半进）；
- 26.4 / 54.4 → `26` / `54`（半以下舍）；
- -26.5 → `-27`（负温）。

### 部署

- 节点由 launch 直接执行 src 下的 `mission_controller.py`，`catkin_install_python`
  只影响 install 空间 → **无需 `catkin_make`**，下次启动 mission 即生效；
- 本地与车端文件 md5 核对一致后 scp 覆盖，车端仓库不提交（沿用 .bak 备份惯例）。

## 结果与结论

- 车端 `python3 src/aic26_decision/test/test_gauge_terminal.py -v`：7 项全部通过；
- 车端格式化自检输出：

```text
温度表读数为27度。湿度表读数为55%。电表读数为235.1kWh
温度表读数为-27度。湿度表读数为12%。电表读数为--
温度表读数为30度。湿度表读数为54%。电表读数为--
```

- 温度/湿度为整数、电表小数保留、缺失段仍为 `--`，符合要求；
- 未改动范围：语音播报 `payload['text']` 与 `gauge.yaml` 模板、`detect_gui.py` Tk 面板
  （显示 `reported_text`）、`gauge_inspect.py` 离线调试的 2 位小数打印；
- `report_terminal.py` 里 `表读数为` 的样例行只是正则自检数据，不受影响。
