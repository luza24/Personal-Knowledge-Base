# Docker Desktop 数据挂载与镜像清理排查

> 整理日期：2026年9月23日 18:22

## 环境信息
- 操作系统：Windows 11 Home China 10.0.26200
- Docker Desktop：WSL2 后端，已开启 **containerd 镜像快照**（`UseContainerdSnapshotter: true`）
- WSL 发行版：Ubuntu、docker-desktop（均为 WSL2）
- 容器环境：Ubuntu 20.04 / osrf/ros:noetic-desktop-full（ROS Noetic）
- 磁盘：C 盘 643G 总 / 546G 已用 / 剩 97G（85%）；E 盘 80G 已满；D 盘挂载 Git

## 报错记录 / 现象
1. **Docker 数据不在默认位置**：数据目录被改到了 `C:\DockerData\DockerDesktopWSL`（而非默认的 `AppData\Local\Docker\wsl`）。
2. **镜像 `docker rmi nginx:latest` 报「No such image / 找不到」**，但 `docker images` 里明明看得到。
3. **ROS / ubuntu 镜像 `docker rmi` 报 conflict**（`unable to remove repository reference ... (must force)`）。

## 涉及文件
- `C:\Users\luza\AppData\Roaming\Docker\settings-store.json` —— 关键配置：
  - `CustomWslDistroDir: "C:\\DockerData\\DockerDesktopWSL"`（数据盘位置）
  - `KubernetesEnabled: true`
  - `UseContainerdSnapshotter: true`
- `C:\DockerData\DockerDesktopWSL\disk\docker_data.vhdx` —— 76GB（镜像/容器/卷数据本体，WSL2 稀疏文件，只增不回收）
- `C:\DockerData\DockerDesktopWSL\main\ext4.vhdx` —— 104MB（docker-desktop 发行版系统盘）
- 容器内代码仓库（**不可删，已推 GitHub**）：
  - `ros1_noetic:/demo01_ws` → `https://github.com/luza24/my_ros.git`
  - `ros_noetic_gazebo:/root/catkin_ws` → `git@github.com:luza24/aic26_smart_community.git`

## 修改方案 / 排查结论
- **数据位置**：Docker 数据仍挂在 C 盘，只是换到了 `C:\DockerData\DockerDesktopWSL`。若迁移可走 GUI `Settings → Resources → Advanced → Disk image location`。
- **镜像删不掉的三个原因**：
  1. ROS/ubuntu 镜像被「已停止容器」引用（`ros_noetic_gazebo`、`listener_container_v2` 占 osrf/ros；`ros1_noetic`、`brave_maxwell` 占 ubuntu:20.04），需先删容器或 `docker rmi -f`。
  2. nginx 镜像 tag 被 containerd snapshotter 的 bug 写坏：`RepoTags` 变成了 `nginx:latest@sha256:...`（digest 被拼进 tag 名），所以按 `nginx:latest` 删不到，**要用镜像 ID 删**（如 `docker rmi abe47724e466`）。
  3. K8s 相关镜像被运行中的控制面容器占用，关 K8s 后自动释放。
- **关闭 K8s**：GUI `Settings → Kubernetes → 取消勾选 Enable Kubernetes → Apply & Restart`；或改 `settings-store.json` 的 `KubernetesEnabled: false`（改前须完全退出 Docker Desktop，否则会被覆盖）。

## 结果与结论
- 数据位置已定位（C 盘 `C:\DockerData\DockerDesktopWSL`）。
- 镜像删不掉的原因已查清（容器占用 / containerd tag bug / K8s 占用）。
- **全程未执行任何删除操作**，仅诊断分析；代码已确认推送到 GitHub（demo01_ws、catkin_ws），但未做清理。
