# 智慧社区复赛：沿马路导航 + 车牌OCR/YOLO 部署方案

> 整理日期：2026年9月21日 22:48

- 竞赛：「全球校园人工智能算法精英大赛·算法应用赛（赛马制）·智慧社区」复赛

## 报错记录
- 本次为方案咨询，无实际报错。

## 涉及文件
- 建议新建 `scripts/waypoint_nav.py`：沿马路中线多点导航脚本（订阅 move_base 的 MoveBaseAction，依次发送 waypoint 目标点）。
- move_base 配置目录 `config/`：`costmap_common_params.yaml`、`global_costmap_params.yaml`、`local_costmap_params.yaml`、`base_local_planner_params.yaml`。
- 建议新建 `yolo_detector.py`：订阅 `/camera/image_raw`，推理后发布 `/yolo/boxes`（BoundingBoxes）。
- 建议新建 `license_plate_ocr.py`：订阅 `/yolo/boxes` 挑出车牌框 → 裁剪 ROI → CRNN/LPRNet 识别 → 发布 `/plate/result`。
- 地图文件：`maps/community_map.pgm` + `.yaml`（由 `map_saver` 生成）。

## 修改方案
1. **沿马路导航（关键认知：gmapping 地图无"马路"语义）**
   - 本质是占据栅格地图（0 可通行 / 100 障碍 / -1 未知），需自己把"马路路线"喂给 move_base。
   - 主推方案：**waypoints 多点导航**。建图 → `map_server` 加载 + AMCL 定位 → Rviz「Publish Point」沿马路中线点取路径点坐标 → 脚本依次发 MoveBaseGoal（朝向用 `atan2` 指向下一点）。
   - 车道线处理：贴图（雷达扫不到）则靠 waypoints 引导；实体则会被当成障碍。限制车辆走马路靠真实边界（护栏/路沿）或手动涂黑 `.pgm` 两侧加虚拟墙。
   - 易踩坑：waypoint 必须用 `map` 坐标系；`wait_for_result()` 会卡住需加超时；导航用 AMCL 而非 gmapping 输出。
2. **车牌 OCR 识别机制（两段式）**
   - ① 车牌检测（YOLO 专门训练 `license_plate` 类别，定位 bounding box）→ ② 字符识别（字符分割+分类，或端到端 CRNN/LPRNet）。
   - 推荐组合：YOLO 检测车牌 + CRNN/LPRNet 识别字符；中国车牌场景建议 HyperLPR / PaddleOCR。
3. **YOLO 部署到仿真车**
   - 本质 = 把算法包成 ROS 节点，订阅相机图像、发布检测框。
   - 路线 A：现成 `darknet_ros`（YOLOv3/v4）；路线 B：自写 PyTorch 节点（适合 v5/v8 自训练模型）。
   - 视觉子模块拓扑：Gazebo相机 → `yolo_detector` → `license_plate_ocr` → 结果回显 Rviz。
   - 识别触发时机（加分点）：导航到巡检点 → 停下对准目标 → 触发识别 → 记录 → 下一站（状态机）。
4. **训练策略**：Gazebo 截图 + labelImg 标注自制四类数据集（红绿灯/人偶/车牌/车道线）；COCO 预训练迁移学习 fine-tune；光照/角度/噪声数据增强呼应 Sim2Real。
