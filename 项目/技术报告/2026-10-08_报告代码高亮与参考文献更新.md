# 技术报告代码高亮与参考文献更新

> 整理日期：2026年10月8日 21:36

## 环境信息
- 操作系统：Windows 11（宿主机），操作对象为桌面 Word 文档（`.docx`）
- 工具：Python 3.8.15 + `python-docx` 1.1.2（脚本处理 docx 的段落/run/字体/颜色）
- 目标文档：《智慧社区》技术报告 `1004改` 系列

## 报错记录
- **GitHub 访问失败**：`git clone` / `git ls-remote` 报 `Recv failure: Connection was reset`，宿主机无代理，无法直接拉取远程仓库。
- **WebFetch 被拦截**：抓取 `api.github.com`、`onlinelibrary.wiley.com`、`pubmed.ncbi.nlm.nih.gov`、`semanticscholar.org`、`mdpi-res.com` 等均提示「无法验证域名安全性」，导致部分文献作者列表无法通过页面抓取补全。
- **GBK 编码报错**：脚本 `print` 含 `−`(U+2212) 等字符时报 `UnicodeEncodeError: 'gbk' codec can't encode`，解决方式为给命令加 `PYTHONIOENCODING=utf-8`。
- **`/tmp` 目录不存在**：`diff`/写临时文件到 `/tmp` 报 `FileNotFoundError`（Windows 无 `/tmp`），改为写到桌面 `C:\Users\luza\Desktop`。

## 涉及文件
- `1004改_代码更新.docx`（源，代码为 Consolas/宋体 9pt 无高亮）
- `1004改_代码更新_代码高亮版.docx`（高亮参考，Calibri/黑体 10.5pt + 语法配色）
- `1004改_代码更新_已高亮.docx`（**输出**，代码已高亮 + 文献已更新）
- `1004改_代码更新_已高亮_引用更新前备份.docx`（改文献前的备份）

## 修改方案

### 任务一：代码片段高亮格式迁移
- **定位代码段**：以段落左侧绿色边框（`w:pBdr` → `w:left` 颜色 `6CE26C`）作为代码块标记；两文件各 584 段代码段（500 行代码 + 84 行空行），按顺序一一对应、文本 0 处不匹配。
- **格式替换**：把高亮版每个代码段的 `w:r`（run）级格式整体 `deepcopy` 到源文件对应代码段，替换掉原有 run。代码段字号由 9pt→10.5pt，字体 Consolas/宋体→Calibri/黑体，并带入语法配色（字符串蓝 `0000FF`、关键字 `006699`+加粗、注释绿 `008000`）。
- **正文不动**：仅处理绿色边框段落，正文（Times New Roman 12pt 等）保持原样。

### 任务二：参考文献更新 + 按引用顺序重新编号
- **现状**：原 12 条文献多数偏老（1992/1997/2004/2007/2009/2016），且正文引用顺序与文献列表编号不一致。
- **换文献**：联网检索 2021–2024 年真实可查文献替换老文献（ROS 2 / 改进 DWA / Regulated Pure Pursuit / 3D LiDAR SLAM 综述 / YOLO 综述 / 灰狼优化 RBPF / 多传感器融合定位等），保留报告中实际用到的中文文献（高翔《视觉SLAM十四讲》、胡春旭《ROS机器人开发实践》、周治国《3D激光雷达SLAM综述》、马永杰《CNN综述》）。
- **重新编号**：提取正文 `[数字]` 标注的首次出现顺序，建立「旧编号→新编号」映射，同步更新正文标注与文献列表，使列表按引用顺序排列。

## 结果与结论
- 代码高亮：584 段代码全部替换为高亮版格式，正文未受影响，输出 `1004改_代码更新_已高亮.docx`。
- 参考文献：12 条文献已更新为近年真实文献并重新编号，正文 12 处引用标注同步改号；改前版本备份为 `1004改_代码更新_已高亮_引用更新前备份.docx`。
- **遗留**：`[4] 3D LiDAR SLAM: A survey`（DOI 10.1111/phor.12497）与 `[9] Fuzzy Dynamic Window Algorithm`（DOI 10.3390/s23198260）两条因网络受限未核到完整作者名，文献列表里**只写题目+期刊+年份+DOI，未编造作者**，需用 DOI 到 Crossref 补全作者。
