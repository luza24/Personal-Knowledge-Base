# ROS 导航停-走抖动与平滑巡检（TEB / pure-pursuit）

> 整理日期：2026年9月22日 16:30

## 环境信息
- 运行环境：Docker 容器（root@docker-desktop），ROS1 Noetic，Gazebo 仿真
- 机器人底盘：四轮**滑移转向（skid-steer）**，底盘本体 0.3m×0.2m，轮中心距 0.264m
- 功能包：`aic26_slam`（建图）、`aic26_navigation`（导航）、`aic26_description`（机器人模型）
- 相关软件：`move_base`、`teb_local_planner`、`dwa_local_planner`、`actionlib`

## 报错记录
1. **航点导航停-走抖动**：用 N 个独立 goal 发 move_base，每个点都减速到停、再加速，速度忽快忽慢不平滑。
2. **插件名拼写错误导致小车不动**：launch 里写成 `global_planner/GlobalPlnner`（少 a）和 `teb_local_planner/TebLocalPlanneROS`（少 r），pluginlib 精确匹配失败，move_base 直接崩溃退出，`rosnode list` 无 `/move_base`，`rostopic list | grep global_plan` 无输出。
3. **小车到起点原地掉头后不动**：goal 发到 `WAYPOINTS[-1]=(1.13,1.60)`，与巡逻起点 `WAYPOINTS[0]` 重合且离车仅 0.58m，move_base 几秒内判定"到达"即停；goal 朝向写死 `w=1(yaw=0)` 与到达朝向差 180°，故原地掉头。
4. **拐弯太早、曲率半径太大**：`round_corners` 的 `r` 从 0.3 误改到 0.5，切点距拐角 0.5m，提前 0.5m 就脱直线进入半径 0.5m 的圆弧，且超过巡逻线到墙余量 0.45m，切内角过狠。
5. **两条路径被拼接成一条**：`LOOP_RAW` 里把第一套 8 点闭环（第 8 行已闭合）+ 第二套 10 点老手动点连写在一起，`round_corners` 把整串当一条折线（末尾又补闭合点），导致车绕一条 19 点的怪路径，而非两条独立路线。

## 涉及文件
- `aic26_navigation/config/teb_local_planner_params.yaml`：TEB 局部规划器参数
- `aic26_navigation/config/costmap_common_params.yaml`：footprint、inflation_radius
- `aic26_navigation/launch/move_base.launch`：插件名、planner_frequency
- `aic26_navigation/scripts/via_point_nav.py`：via-point 路径覆盖节点（方案 A）
- `aic26_navigation/scripts/patrol.py`：pure-pursuit 巡逻节点（最终方案，含圆角、前瞻减速、双闭环交替）

## 修改方案
1. **DWA 参数优化**（缓解停-走）：`acc_lim_x` 1.0→0.4（加减速都变缓）、`xy_goal_tolerance` 0.2→0.35、`yaw_goal_tolerance` 0.1→0.2。
2. **footprint 按 SDF 精确计算**：底盘 `<size>0.3 0.2 0.08</size>` → `footprint: [[-0.15,-0.10],[-0.15,0.10],[0.15,0.10],[0.15,-0.10]]`；`inflation_radius` 0.05→0.20（原值太小，贴墙易卡）。
3. **换 TEB 局部规划器**：`base_local_planner = teb_local_planner/TebLocalPlannerROS`，关键参数 `global_plan_overwrite_orientation: true`（忽略中间点朝向，滑过路点不对正）。
4. **插件名修正**：`GlobalPlanner`、`TebLocalPlannerROS`（各补回缺失字母）。
5. **via-point 方案（方案 A）**：发一个 goal 到终点激活 move_base，再以 5Hz 把插值后的稠密 `Path` 发到 `/move_base/TebLocalPlannerROS/global_plan`。
6. **最终方案 pure-pursuit 巡逻（方案 A'）**：因"闭合圈用单 goal 必然第一次到达即停"，改用不依赖 move_base 的 pure-pursuit：读 `/odom`、发 `/cmd_vel`，`v=MAX_V·cos(α)`、`ω=2v·sin(α)/L`。滑移底盘避免原地转，最低速不归零。
7. **圆角过渡 `round_corners`**：只写直角顶点，拐角自动替换为半径 `r` 的圆弧，避免手动切角点叠加导致轨迹漂。90° 时切点距顶点 `d = r/tan45° = r`。`r` 受"巡逻线到墙余量 0.45m"约束，`r>0.3` 即切内角过狠，**合理区间 0.15~0.20**。
8. **曲率前瞻减速**：`point_ahead` 额外返回前方 LOOKAHEAD 距离内的累计转向角 `turn`，主循环 `v_turn = MAX_V·(1−SLOW_DEPTH·min(1, turn/90°))`，让车**进弯前**就减速（原 `v=MAX_V·cosα` 只在车头已偏向时才减速，导致全速冲进拐角）。
9. **双闭环交替巡逻（状态机）**：`LOOPS=[loop_a, loop_b]`，用 `started` 标志 + `DEPART_DIST`/`RETURN_DIST` 判定"离开起点后再次回到起点附近"即切换下一条，`current_idx=(current_idx+1)%len(LOOPS)`。两条路径需共享起点。

## 结果与结论
- 插件名修正后 `rostopic list | grep -iE 'teb|global_plan'` 正常列出 `/move_base/TebLocalPlannerROS/global_plan` 等话题。
- 确认 via-point 路径已灌入（`global_plan` 有 237 个点）。
- 结论：**闭合巡逻圈不能用"单个 goal"实现平滑**；要平滑巡逻用 pure-pursuit（无绕障），要绕障用自定义全局规划器插件（方案 B，C++，未实现）。
- 拐弯太早/半径太大：把 `r` 0.5→0.18、`LOOKAHEAD` 0.5→0.3、`MAX_V` 0.4→0.28 即可同时解决（r 决定路径形态，LOOKAHEAD 决定跟线贴合度，MAX_V 决定是否外冲）。
- 两条闭环交替已实现，切换时终端打印 `完成一圈，切换到第 N 条路径`。
